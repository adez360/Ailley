## 1. 死亡流程

```
                ┌──────────────────┐
                │  死亡條件成立     │  health ≤ 0
                └────────┬─────────┘  或餓死／渴死
                         ▼
            ┌────────────────────────┐
            │ ① 記錄 last_words       │  臨終遺言，可為 null
            │ ② 記錄 death_cause      │  死亡原因
            │ ③ conditions 清空       │
            │    只留 petrified       │
            └────────────┬───────────┘
                         ▼
            ┌────────────────────────┐
            │   石化・停留原地        │
            │   本體變成灰色          │
            │   屍體開始 decay        │
            └────────────┬───────────┘
                         │
        ┌────────────────┴────────────────┐
        │ 他人偵測到                       │ decay 達 100
        ▼                                  ▼
┌────────────────────┐          ┌────────────────────┐
│  AI 自行決定是否搬運 │          │  自動立「無名碑」   │
│  （不強制）          │          │  確保死亡必被記錄   │
└─────────┬──────────┘          └────────────────────┘
          │ 決定搬運
          ▼
┌────────────────────┐
│  搬運至墓園         │  loc_cemetery
│  loc_cemetery       │
└─────────┬──────────┘
          ▼
┌────────────────────┐
│      已安葬         │
│  墓碑面板完整開放    │
└────────────────────┘
```

### 死亡觸發頻率

日常觀察模式下，死亡觸發為**溫和／低頻**（意外、老化為主），避免博弈感過重影響調性。

## 2. 死亡相關欄位

```json
"death": {
  "is_dead": true,
  "death_tick": 8642,
  "death_day": 60,
  "death_cause": "在森林被大型獵物所傷，失血過多",
  "death_location_id": "loc_forest",
  "last_words": "早知道就不該一個人去。",
  "corpse_decay": 34,
  "is_buried": false,
  "grave_id": null
}
```

| 欄位 | 型別 | 誰寫 | 說明 |
| --- | --- | --- | --- |
| `is_dead` | bool | 引擎 |  |
| `death_cause` | string | **引擎** | 中文自然語言，由引擎彙整，**不讓 LLM 潤飾** |
| `last_words` | string | null | **LLM** | 臨終遺言，可為 null（來不及說） |
| `corpse_decay` | int | 引擎 | 0–100，達 100 自動立無名碑 |
| `is_buried` | bool | 引擎 | 是否已安葬 |
| `grave_id` | string | null | 引擎 | 墓碑 ID |

### `last_words` 產生規則　【推測待確認】

| 死因 | 是否有機會留遺言 |
| --- | --- |
| 餓死／渴死／老化 | ✔ 有，死亡前一 tick 詢問 AI |
| 傷重不治 | ✔ 有 |
| 瞬間死亡（Flag 關鍵字觸發） | ✘ `last_words = null` |

## 3. 屍體處理

### 3-1 石化本體

- 死亡後角色本體**停留原地變成灰色**，不消失
- 其他角色移動經過時可偵測到
- 屍體佔用該地點的容量【推測待確認】

### 3-2 搬運

| 項目 | 規格 |
| --- | --- |
| 誰能搬 | 任何偵測到屍體的角色 |
| 是否強制 | **否**。由 AI 自行決定要不要搬 |
| 搬運目的地 | `loc_cemetery` 墓園 |
| 搬運耗時 | 【待填】 |
| 搬運時可否被中斷 | 【待確認】 |

> 💡 「有人死在路邊，村民各自決定要不要理他」本身就是高觀察價值的橋段。**絕對不要做成自動搬運。**
> 

### 3-3 屍體腐壞

```
每 tick：corpse_decay += 【待填】建議 0.7

corpse_decay = 100 且 is_buried = false
        ↓
自動立「無名碑」
```

**無名碑**的意義：確保**每一個死亡都會被記錄**，即使沒有人願意搬他。無名碑上不顯示遺言與生平，只有一行「無人知曉他是誰」與死亡日期。

## 4. 墓碑

### 4-1 結構

```json
{
  "grave_id": "grave_007",
  "npc_id": "npc_017",
  "name": "TAMMY",
  "is_anonymous": false,
  "buried_tick": 8698,
  "buried_by": "npc_003",
  "death_cause": "在森林被大型獵物所傷，失血過多",
  "last_words": "早知道就不該一個人去。",
  "words_to_creator": "你把我設計成連話都懶得講，那你現在是想聽什麼？",
  "life_highlights": [
    "第 12 天，第一次採到藥草",
    "第 29 天，和 NEON 在廣場起了衝突",
    "第 41 天，救了溺水的 CHO"
  ],
  "epitaphs": [
    { "npc_id": "npc_003", "content": "我們吵過架，但我沒想過他會死在那裡。" }
  ]
}
```

### 4-2 四個內容欄位

| 欄位 | 來源 | 規則 |
| --- | --- | --- |
| `last_words` | **死者的 LLM** | 臨終遺言，可為 null |
| `words_to_creator` | **死者的 LLM**（建角時生成） | 對造物主的一句吐槽，見《01》§1-4 |
| `life_highlights` | **引擎彙整** | 由 L4 核心記憶與重大事件流產出，**絕不讓 LLM 潤飾** |
| `epitaphs` | **他人的 LLM** | 活人悼詞，每人限 1 條，可覆寫 |

> ⚠️ `life_highlights` 由引擎彙整是刻意的設計。讓 LLM 潤飾會產生美化過的假履歷，失去「這是真的發生過的事」的重量。
> 

### 4-3 顯示規則

| 狀態 | 墓碑面板顯示 |
| --- | --- |
| **未安葬** | **不顯示** `last_words` 與 `life_highlights`。只有死亡原因與日期 |
| 已安葬 | 全部顯示 |
| 無名碑 | 只有「無人知曉他是誰」與死亡日期 |

> 未安葬時不顯示遺言與生平——這給了「搬運」這個行為實質的意義：**沒有人願意搬他，他的一生就沒有人知道。**
> 

### 4-4 悼詞 `epitaphs`

| 項目 | 規格 |
| --- | --- |
| 誰能留 | 任何抵達墓園的角色 |
| 每人上限 | 1 條 |
| 可否覆寫 | ✔ 可，覆寫後舊的不保留 |
| 字數上限 | 【待填】建議 40 字 |
| 是否強制 | ✘ 由 AI 自行決定 |

## 5. 死亡對其他角色的影響　【推測待確認】

| 事件 | 效果 |
| --- | --- |
| 目擊死亡 | 中斷當前行動；該事件 `importance` 通常會被 AI 評高分，進 L4 |
| 發現屍體 | 引擎送出事件，**不指定情緒**，AI 自行反應 |
| 死者是關係密切者 | 引擎不做特別處理——關係數值已在 prompt 裡，AI 自己知道 |
| 全村死亡 | 世界結束，進入完結總結（文字呈現） |

> 依《00》原則二，引擎只送出「你看到 TAMMY 倒在森林裡，他已經死了。」這樣的事實句，不送任何情緒或關係變動。悲傷、冷漠、還是鬆一口氣，由 AI 自己決定。
>

## 6. 墓園地點

| 項目 | 規格 |
| --- | --- |
| `location_id` | `loc_cemetery` |
| 可執行行動 | `move` / `bury`（安葬）／ `epitaph`（留悼詞）／ `rest` |
| 容量 | 6【推測待確認】 |
| 玩家互動 | 點擊墓碑查看完整內容 |

## 7. 圖書館連動

死亡事件會寫入圖書館（跨局永久保存）：

| 記錄項目 | 說明 |
| --- | --- |
| 死亡事件 | 依稀有度給予成就 |
| `words_to_creator` | **只有在角色死亡後才會被收錄**——這是玩家唯一能完整看到它的地方 |
| 完結世界總結 | 採文字呈現 |
