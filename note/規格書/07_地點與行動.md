### 1-1 地點資料結構　【推測待確認】

所有地點筆記共用下列格式，範例取自 [[森林]]（目前唯一填滿實際數值的地點）：

```json
{
  "location_id": "loc_forest",
  "name": "森林",
  "desc": "樹影很密，聽得到不知名的動物聲。",
  "capacity": 4,
  "danger": 20,
  "resources": ["small_game", "large_game"],
  "available_actions": ["hunt_small", "hunt_large", "move", "rest"],
  "regen": { "small_game": 36, "large_game": 144 }
}
```

| 欄位 | 說明 |
| --- | --- |
| `desc` | 一句話環境描述，注入 prompt 用 |
| `capacity` | 同時容納人數上限，滿員則無法進入 |
| `danger` | 環境危險度 0–100，扣減行為成功率 |
| `resources` | 該地點可產出的資源 |
| `regen` | 資源再生所需 tick 數（草藥採收後需等待才會再生） |

## 2. 行動清單

行為的成功率公式與參數見《01-2》。本節定義**有哪些行動**與**分類規則**。溝通類（A）的行動與社交規則獨立在《[[11_人際互動與社交行為]]》，不在本節。

### 2-1 四大類

| 類別 | 特性 | 是否需要對方同意 |
| --- | --- | --- |
| **A 溝通類** | 對他人說話 —— 見《[[11_人際互動與社交行為]]》 | 依行動而定 |
| **B 工作與消費類** | 產出或消耗資源 | 否 |
| **C 動作與移動類** | 改變自身狀態或位置 | 否 |
| **D 敵對類** | 對他人造成損害 | 否 |

### 2-2 B 工作與消費類

| `action` | 中文 | 可用地點 |
| --- | --- | --- |
| `hunt_small` | 打獵（小型） | [[森林]] |
| `hunt_large` | 打獵（大型） | [[森林]] |
| `gather` | 採集藥草 | [[藥草叢]] |
| `fish` | 捕魚 | [[湖泊]] |
| `buy` | 購買 | 各商鋪 |
| `sell` | 販售 | 各商鋪 |
| `eat` | 進食 | 任意（需有食物） |
| `drink` | 喝水／喝酒 | 任意（需有飲品） |

### 2-3 C 動作與移動類

| `action` | 中文 | 說明 |
| --- | --- | --- |
| `move` | 移動 | 需指定 `location_id` |
| `sleep` | 睡覺 | 自己家回復量最大 |
| `nap` | 打盹 | 與睡覺同模組，體力回復值較低 |
| `rest` | 休息 | 原地發呆，小幅回復體力 |
| `wash` | 清潔 | 提升 `hygiene`，需在 [[湖泊]] 或 [[深井]] |
| `idle` | 發呆 | **系統兜底用**，AI 逾時或失敗時執行 |

### 2-4 D 敵對類

| `action` | 中文 | 說明 |
| --- | --- | --- |
| `steal` | 偷竊 | 含被目擊獨立判定，見《01-2》§4 |
| `attack` | 攻擊 | 造成 `injury`，關係大幅下降 |

## 3. 偵測與範圍　【推測待確認】

Godot 端負責偵測「這個角色現在看得到／聽得到什麼」。

| 範圍 | 半徑（格） | 內容 |
| --- | --- | --- |
| 視覺 | 5 | 看得到的角色與物件 |
| 聽覺（一般說話） | 3 | 聽得到的對話 |
| 聽覺（`shout`） | 8 | 大叫可提高偵測範圍 |
| 天神之石 | 6 | 玩家投放話語的影響範圍 |

### 動態擴大偵測範圍

Godot 端已規劃「方圓幾格內事物偵測」與動態擴大機制。`shout` 是目前唯一會改變偵測半徑的行動。

## 5. 地點與可用行動的對應

`available_actions` 由 Godot 端依「地點 ＋ 角色狀態 ＋ 持有物」過濾後給 AI（見《04》§4-2）。

```
地點的 available_actions
        │
        ├─ 減去：角色狀態不允許的（力竭時不能打獵）
        │
        ├─ 減去：缺少前置物品的（沒有食物就沒有 eat）
        │
        └─ 加上：全地點通用的（move / rest / idle / talk）
                │
                ▼
        送給 AI 的 available_actions
```

> ⚠️ 過濾一律由引擎判斷，不交給 LLM。AI 只能從清單裡選，選不在清單裡的視為失敗。
> 

**過濾（拿掉選項）只用於角色狀態不允許／缺前置物品**——這兩種是「客觀上做不到」，AI 看不到這個選項不算少自由度。**社會性限制（名聲過低、被禁止進入的地點等）不走過濾**：選項仍留在 `available_actions` 裡，AI 能選，由引擎判定失敗並給理由，貼近《00》原則一「LLM 決定想做什麼，引擎決定做不做得到」——AI 保有「明知可能被拒也要去試」的自由。範例見《08》§5「交易規則」#3。
