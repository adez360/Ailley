# 04｜Godot 與 AI 資料介接規格

**閱讀對象**：後端組・前端組・AI 組
**文件性質**：通訊契約。Godot 端與 AI 後端之間所有資料交換的格式以本文件為準。
**前置閱讀**：《00 設計原則與架構》、《01-3 Prompt 注入與資料傳送》

---

## 1. 系統架構

```
┌──────────────────────────────────────────────────────────────┐
│                     Godot 4.x（遊戲端）                        │
│  ────────────────────────────────────────────────────────    │
│  • 世界模擬（移動、碰撞、偵測範圍、時間推進）                    │
│  • 成功率判定與擲骰（《01-2》）                                 │
│  • 狀態套用與存檔                                              │
│  • UI 渲染（立繪、內心狀態視窗、天神之石輸入框）                 │
└───────────────────────────┬──────────────────────────────────┘
                            │  HTTP + JSON（localhost）
                            │  非同步，不阻塞主執行緒
                            ▼
┌──────────────────────────────────────────────────────────────┐
│                    AI 後端（Python）                           │
│  ────────────────────────────────────────────────────────    │
│  • Prompt 組裝（Tier 分級、事實句、兜底句）                     │
│  • GBNF grammar 動態產生                                       │
│  • 決策佇列與排程（DES）                                        │
│  • 記憶檢索（Vector DB）                                        │
└───────────────────────────┬──────────────────────────────────┘
                            │  HTTP（llama.cpp server API）
                            ▼
┌──────────────────────────────────────────────────────────────┐
│              llama-server（--parallel 5, ctx 16000）           │
└──────────────────────────────────────────────────────────────┘
```

### 職責切分原則

| 這件事 | 誰做 |
| --- | --- |
| 決定「想做什麼」 | AI 後端（LLM） |
| 決定「做不做得到」 | **Godot** |
| 擲骰 | **Godot** |
| 數值增減與存檔 | **Godot** |
| 組 Prompt、過濾資料 | AI 後端 |
| 記憶寫入與檢索 | AI 後端 |

> ⚠️ 擲骰與數值變更**一律在 Godot 端**。AI 後端不得直接改動任何角色數值，只能回傳意圖。
>

## 2. 通訊方式

| 項目 | 規格 |
| --- | --- |
| 協定 | HTTP/1.1 |
| 位址 | `http://127.0.0.1:8420`（連接埠【待填】） |
| 資料格式 | JSON，UTF-8 |
| Godot 端 | `HTTPRequest` node，非同步 |
| 編碼 | `JSON.stringify()` / `JSON.parse_string()` |

### 為什麼是 HTTP 不是 WebSocket

Godot 內建 `HTTPRequest`，零額外依賴；本專案是單機遊戲、單向請求為主（Godot 主動問、AI 回答），不需要伺服器主動推播。若日後要做多人連線模式再評估 WebSocket。

---

## 3. 端點清單

| 端點 | 方法 | 方向 | 用途 |
| --- | --- | --- | --- |
| `/health` | GET | Godot → AI | 檢查模型是否就緒 |
| `/tick` | POST | Godot → AI | 每 tick 批次要求決策 |
| `/event` | POST | Godot → AI | 推送即時事件（天神之石） |
| `/generate/words` | POST | Godot → AI | 建角時生成 `words_to_creator` |
| `/memory/reflect` | POST | Godot → AI | 睡眠反思、記憶壓縮 |

## 4. 封包格式

### 4-1 `/health`

**回應**

```json
{
  "status": "ready",
  "model": "local-7b",
  "slots_total": 5,
  "slots_busy": 0,
  "protocol_version": "1.0"
}
```

`status` 為 `ready` / `loading` / `error`。Godot 啟動時先打這支，未 ready 前不開始跑 tick。

### 4-2 `/tick`　批次決策請求

**Godot → AI**

一次送出所有需要決策的 NPC（對應 llama-server 的 `--parallel 5`）。

```json
{
  "protocol_version": "1.0",
  "request_id": "req_00001234",
  "tick": 4210,
  "game_time": { "day": 30, "hour": 14, "minute": 20 },
  "npcs": [
    {
      "npc_id": "npc_017",
      "snapshot": {
        "physical": {
          "hunger":     { "value": 62, "label": "很餓" },
          "thirst":     { "value": 38, "label": "有點渴" },
          "stamina":    { "value": 45, "label": "有些疲倦" },
          "sleepiness": { "value": 20, "label": "還算清醒" },
          "hygiene":    { "value": 55, "label": "普通" },
          "alcohol":    { "value": 0,  "label": "清醒" },
          "health":     { "value": 88, "label": "健康" },
          "injury":     { "value": 12, "label": "輕微擦傷" }
        },
        "emotion": {
          "type": "anger", "intensity": 78, "duration_left": 6
        },
        "conditions": [ { "type": "injured", "turns_left": 8 } ],
        "current_goal": "把藥草賣掉，換錢買一把好一點的刀",
        "today_plan": ["去藥草叢採集", "到藥草鋪賣掉", "晚上去餐酒館"],
        "last_action_result": {
          "action": "steal",
          "target": "npc_003",
          "success": false,
          "reason": "現場有兩名目擊者，你臨陣退縮了"
        },
        "location": {
          "id": "loc_herb_field",
          "name": "藥草叢",
          "desc": "一片半人高的草叢，泥土有點濕。"
        },
        "fact_lines": [
          "你已經半天沒和任何人說過話了。"
        ],
        "present_npcs": [
          {
            "npc_id": "npc_003",
            "name": "NEON",
            "appearance_text": "他綁著一頭紅色長髮，穿著沾滿油汙的工作服。",
            "relation": { "affinity": -40, "trust": 15, "familiarity": 72, "debt": -20 }
          }
        ],
        "available_actions": ["gather", "move", "talk", "rest", "eat", "steal"],
        "economy": {
          "money": 300,
          "inventory": [
            { "item_id": "herb", "count": 4, "decay": 22, "durability": 100 }
          ]
        },
        "injected_lines": []
      }
    }
  ]
}
```

#### 欄位說明

| 欄位 | 必填 | 說明 |
| --- | --- | --- |
| `protocol_version` | ✔ | 版號不合時 AI 端回 `400` |
| `request_id` | ✔ | Godot 端產生，回應必須帶回同一個 |
| `tick` | ✔ | 全域 tick 計數 |
| `physical.*.value` | ✔ | 數值本體 |
| `physical.*.label` | ✔ | **中文形容詞，缺一不可**（見《01-3》§6） |
| `fact_lines` | ✔ | 引擎產生的事實句陣列，無則傳 `[]` |
| `present_npcs` | ✔ | **只放在場的人**，無則傳 `[]` |
| `available_actions` | ✔ | 由 Godot 依地點與狀態過濾後給定 |
| `injected_lines` | ✔ | 特殊注入行（如 `words_to_creator` 觸發），無則傳 `[]` |

> ⚠️ **決策階段只讀 tick 開始前的快照**。整包 `/tick` 的資料必須在同一個時間點截取，套用階段才序列處理，否則會有 race condition。
> 

**AI → Godot**

```json
{
  "protocol_version": "1.0",
  "request_id": "req_00001234",
  "tick": 4210,
  "decisions": [
    {
      "npc_id": "npc_017",
      "action": "gather",
      "target": null,
      "location_id": "loc_herb_field",
      "monologue": "藥草再不採就要被別人拿光了。",
      "speech": null,
      "speech_volume": "normal",
      "emotion": { "type": "neutral", "intensity": 30 },
      "current_goal": "把藥草賣掉，換錢買一把好一點的刀"
    }
  ],
  "meta": {
    "latency_ms": 820,
    "failed": []
  }
}
```

#### 欄位說明

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| `action` | enum | GBNF 靜態 enum 約束 |
| `target` | string | null | 目標角色或物品 ID，GBNF 動態產生可選值 |
| `location_id` | string | null | 移動目的地，GBNF 動態產生可選值 |
| `monologue` | string | **必填**，內心獨白 |
| `speech` | string | null | **可為 null**——AI 自己決定說不說、說多長 |
| `speech_volume` | enum | `whisper` / `normal` / `shout`，GBNF 靜態 enum |
| `emotion` | object | AI 自行宣告 |
| `current_goal` | string | AI 可隨時改寫，上限 40 字 |
| `meta.failed` | array | 決策失敗的 `npc_id` 清單，Godot 對這些人執行 `idle` |

> ⚠️ 回應中**不得包含任何數值變更**。AI 不可回傳 `hunger`、`money`、`relations` 等欄位——那些一律由 Godot 計算。
>

### 4-3 `/event`　天神之石事件

**Godot → AI**

```json
{
  "protocol_version": "1.0",
  "event_id": "evt_1043",
  "event_type": "divine_stone",
  "tick": 4210,
  "content": "北邊的井裡有東西",
  "credibility": 0.5,
  "audience": [
    {
      "npc_id": "npc_017",
      "snapshot": { "…": "同 /tick 的 snapshot 結構" },
      "words_to_creator": {
        "triggered": true,
        "content": "你把我設計成連話都懶得講，那你現在是想聽什麼？"
      }
    }
  ]
}
```

| 欄位 | 說明 |
| --- | --- |
| `content` | 玩家原句，未經處理 |
| `credibility` | Event Parser 給的可信度 0.0–1.0，AI 自行決定信不信 |
| `audience` | 範圍內聽得到的角色 |
| `words_to_creator.triggered` | **Godot 端擲骰決定**，為 `true` 時 AI 才把該句注入 prompt |

**觸發規則**（Godot 端判定）：

```
玩家在天神之石輸入一段話
        │
        ▼
Event Parser → event_type / content / credibility
        │
        ▼
判斷範圍內有哪些角色
        │
        ├─► 一般反應（每個人都跑）
        │
        └─► words_to_creator 觸發判定（每個人各自骰）
                │
                ├─ is_spoken == true ──► triggered = false
                │
                └─ 擲骰【機率待填】
                        ├─ 成功 ──► triggered = true
                        └─ 失敗 ──► triggered = false
```

**AI → Godot**

```json
{
  "protocol_version": "1.0",
  "event_id": "evt_1043",
  "reactions": [
    {
      "npc_id": "npc_017",
      "believed": false,
      "monologue": "井裡有東西？誰知道是誰在講話。",
      "speech": "你把我設計成連話都懶得講，那你現在是想聽什麼？",
      "spoke_words_to_creator": true,
      "emotion": { "type": "surprise", "intensity": 55 }
    }
  ]
}
```

| 欄位 | 說明 |
| --- | --- |
| `believed` | AI 自行決定信不信這段話 |
| `spoke_words_to_creator` | AI **實際上有沒有把那句話說出口**。為 `true` 時 Godot 才寫入 `is_spoken` / `spoken_at` / `trigger` |

> ⚠️ `speech` 若為 `words_to_creator` 的內容，**只送給玩家 UI**（浮動文字／內心狀態視窗），**不寫入其他 NPC 的對話事件與記憶**。
>

### 4-4 `/generate/words`　建角時生成

**Godot → AI**

```json
{
  "protocol_version": "1.0",
  "npc_id": "npc_017",
  "system_prompt": "你正在扮演一個遊戲角色。\n\n【行為準則】\n- 你極度自私狡猾…"
}
```

**AI → Godot**

```json
{
  "protocol_version": "1.0",
  "npc_id": "npc_017",
  "content": "你把我設計成連話都懶得講，那你現在是想聽什麼？",
  "retries": 0
}
```

生成規則見《01》§1-4。違規（提及遊戲內容或數值）時 AI 端自行重試，`retries` 回報重試次數。

### 4-5 `/memory/reflect`　睡眠反思

**Godot → AI**

```json
{
  "protocol_version": "1.0",
  "npc_id": "npc_017",
  "day": 30,
  "events": [ { "…": "當日事件流" } ],
  "personality": { "…": "10 項現值" }
}
```

**AI → Godot**

```json
{
  "protocol_version": "1.0",
  "npc_id": "npc_017",
  "summary": "今天採了藥草但沒賣掉，跟 NEON 又吵了一架。",
  "personality_delta": { "grudge": 2, "sociability": -1 },
  "today_plan": ["去藥草鋪賣掉藥草", "避開 NEON", "晚上去餐酒館"]
}
```

| 欄位 | 說明 |
| --- | --- |
| `personality_delta` | **單項絕對值上限 3**。超過時 Godot 端夾制，不採信 |
| `today_plan` | 2~4 件事 |

## 6. 錯誤處理

| 狀況 | Godot 端行為 |
| --- | --- |
| `/health` 未 ready | 不開始跑 tick，顯示「模型載入中」 |
| 逾時（> 5 秒【待填】） | 該 NPC 本 tick 執行 `idle`，寫入 `last_action_result` |
| HTTP 5xx | 同上，寫入 log |
| JSON 解析失敗 | 重試 1 次，仍失敗則 `idle` |
| `request_id` 不符 | 丟棄該回應，視為逾時 |
| `protocol_version` 不符 | 停止並顯示錯誤，不得靜默降級 |
| AI 回傳不存在的 `target` | 判定為失敗，`reason` 寫「你要找的人不在這裡」 |
| AI 回傳數值變更欄位 | **忽略該欄位**，寫入 log |

### `idle` 兜底

逾時或失敗時，Godot 寫入：

```json
{
  "action": "idle",
  "target": null,
  "success": true,
  "reason": null
}
```

角色原地發呆一個 tick，體力小幅回復。**絕不讓角色因為 AI 沒回應而卡住或消失。**

## 7. 資料型別對應

| Godot（GDScript） | JSON | Python |
| --- | --- | --- |
| `int` | number | `int` |
| `float` | number | `float` |
| `String` | string | `str` |
| `bool` | true / false | `bool` |
| `Array` | array | `list` |
| `Dictionary` | object | `dict` |
| `null` | null | `None` |

### 注意事項

| # | 事項 |
| --- | --- |
| 1 | Godot 的 `JSON.parse_string()` 會把所有 number 轉成 `float`。整數欄位取值後要 `int()` 轉回 |
| 2 | 中文字串一律 UTF-8，不做 escape |
| 3 | `null` 與空字串 `""` 意義不同：`speech: null` = 不說話，`speech: ""` = 錯誤格式 |
| 4 | 時間戳一律 ISO 8601 UTC（`2026-08-08T10:00:00Z`） |

## 8. GBNF 約束範圍

| 欄位 | 約束方式 |
| --- | --- |
| `action` | 靜態 enum |
| `emotion.type` | 靜態 enum（8 值） |
| `speech_volume` | 靜態 enum（3 值） |
| `target` | **動態產生**，每次呼叫前由 `build_grammar_for_call()` 依在場角色與物品組成 |
| `location_id` | **動態產生**，依可移動地點組成 |
| `monologue` / `speech` | 不約束內容，只約束型別（string / null） |

> 動態規則必須在每次呼叫前重建。若沿用上一次的 grammar，AI 可能指向已經離場的角色。
>
