## 1. 記憶四層架構

```
╔══════════════════════════════════════════════════════════════╗
║  L1  短期工作記憶                          固定 8 條，全給     ║
║  ────────────────────────────────────────────────────────    ║
║  最近 5~10 句對話 ＋ 最近發生的事                              ║
║  → 每 tick 滾動，超出即擠掉最舊的                              ║
╠══════════════════════════════════════════════════════════════╣
║  L2  近期記憶                              不定筆數，需過濾    ║
║  ────────────────────────────────────────────────────────    ║
║  當日至近三日的事件                                            ║
║  → 睡覺反思時壓縮成摘要，晉升或淘汰                            ║
╠══════════════════════════════════════════════════════════════╣
║  L3  長期記憶庫（Vector DB）               語意檢索取 3~5 條   ║
║  ────────────────────────────────────────────────────────    ║
║  跨日事件，依當前情境語意檢索                                  ║
║  → 依重要度分級，最次要者可定期刪除以省記憶體                   ║
╠══════════════════════════════════════════════════════════════╣
║  L4  核心記憶                              固定，全給          ║
║  ────────────────────────────────────────────────────────    ║
║  永不遺忘的重大事件（死亡目擊、重大背叛、關係轉折）             ║
║  → 上限【推測待確認】5 條                                      ║
╚══════════════════════════════════════════════════════════════╝
```

### 注入規則（沿用《01-3》§2）

| 層 | 筆數 | 注入方式 |
| --- | --- | --- |
| L1 | 固定 8 條 | **全給** |
| L2 | 不定 | 過濾後給 |
| L3 | 不定 | 語意檢索取 3~5 條 |
| L4 | 固定 | **全給** |

固定筆數的全給，不定筆數的才過濾。過濾一律由引擎判斷，不交給 LLM。

## 2. 記憶結構

```json
{
  "memory_id": "mem_004821",
  "npc_id": "npc_017",
  "level": 3,
  "created_tick": 4180,
  "created_day": 29,
  "content": "NEON 說我偷了他的工具，當著三個人的面。",
  "valence": "negative",
  "importance": 78,
  "related_npcs": ["npc_003"],
  "location_id": "loc_square",
  "decay_value": 62,
  "embedding": [ "…" ]
}
```

| 欄位 | 型別 | 誰寫 | 說明 |
| --- | --- | --- | --- |
| `level` | int | 引擎 | 1~4 |
| `content` | string | **LLM** | 一句話，上限 60 字【推測待確認】 |
| `valence` | enum | **LLM** | `positive` / `negative` / `neutral` |
| `importance` | int | **LLM** | 0–100，見 §3 |
| `related_npcs` | array | 引擎 | 涉及的角色 ID |
| `decay_value` | int | 引擎 | 100 起算，歸零則刪除 |
| `embedding` | vector | 引擎 | 供 L3 語意檢索 |

## 3. 重要度評分

**由 LLM 自行評分。** 引擎不做加權——不同角色對同一事件的在意度差異，交由 AI 自行判斷。

### 評分指示（寫入睡眠反思的呼叫中）　【推測待確認】

```
針對今天發生的每一件事，用 0~100 給一個「對你來說有多重要」的分數。
不是這件事客觀上有多嚴重，而是「你」有多在意。
```

### 分級對照　【推測待確認】

| `importance` | 去向 |
| --- | --- |
| 0–29 | 直接丟棄，不寫入記憶庫 |
| 30–59 | 寫入 L2，三日後若未被檢索則淘汰 |
| 60–89 | 晉升 L3 長期記憶庫 |
| 90–100 | 晉升 L4 核心記憶，永不刪除 |

> L4 滿額時（上限 5 條），新的 90+ 記憶取代最舊的一條，被取代者降級為 L3。
>

## 4. 記憶衰減

### 4-1 衰減公式　【推測待確認】

```
每遊戲日執行一次：

正面／中性記憶：decay_value −= 基礎衰減率
負面記憶：      decay_value −= 基礎衰減率 × (100 − grudge) / 50

基礎衰減率 = 3

decay_value ≤ 0 → 刪除（L4 不衰減）
```

**範例**：同一件負面事件，`decay_value` 從 100 開始

| 角色 | `grudge` | 每日衰減 | 撐幾天 |
| --- | --- | --- | --- |
| 健忘的人 | 20 | 4.8 | 約 21 天 |
| 一般人 | 50 | 3.0 | 約 33 天 |
| 記仇的人 | 85 | 0.9 | 約 111 天 |

> 💡 一個參數就撐起「有人隔天就忘、有人記三個月」的角色差異。這是 `grudge` 在引擎中的主要用途。
> 

### 4-2 被檢索會延長壽命

記憶每次被 L3 語意檢索命中，`decay_value` 回補 +10【推測待確認】，上限 100。

常被想起的事忘得慢——這符合直覺，也讓「反覆糾結的往事」自然形成。

## 5. 睡眠反思流程

```
角色進入睡眠
        │
        ▼
┌────────────────────────────────────────┐
│ ① 收集當日事件流                        │
├────────────────────────────────────────┤
│ ② 送 /memory/reflect 給 AI 後端（《04》）│
│    → LLM 產出：                         │
│       • 當日摘要（一句話）               │
│       • 每件事的 importance 評分         │
│       • personality_delta（單項 ±3）     │
│       • today_plan（2~4 件）             │
├────────────────────────────────────────┤
│ ③ 引擎依 importance 分級寫入 L2/L3/L4    │
├────────────────────────────────────────┤
│ ④ 執行記憶衰減（§4-1）                   │
├────────────────────────────────────────┤
│ ⑤ 清空 L1 短期工作記憶                   │
├────────────────────────────────────────┤
│ ⑥ 套用 personality_delta（引擎夾制 ±3）  │
└────────────────┬───────────────────────┘
                 ▼
            回到決策循環
```

> ⚠️ `personality_delta` 單項絕對值超過 3 時，引擎夾制，不採信 LLM 的數字。

## 6. 酒精導致的記憶遺失

依酒量與 `alcohol` 濃度遺失部分記憶，**程式碼寫死**，不交由 LLM 判斷。

### 判定　【推測待確認】

```
若當日最高 alcohol > 60：
    當日 L2 記憶有 (alcohol − 60) × 1.5% 的機率逐條被標記為「模糊」

「模糊」記憶的處理：
  • content 前綴加上「你隱約記得」
  • importance 降至原值的一半
  • 不進入 L4
```

醉到斷片的角色隔天記不清昨晚做了什麼——包括自己說出口的真心話。

## 7. 語意檢索

| 項目 | 規格 |
| --- | --- |
| 檢索來源 | L3 長期記憶庫 |
| 每次取回 | 3~5 條 |
| 檢索查詢 | 當前情境（地點＋在場角色＋current_goal）組成的字串 |
| 向量資料庫 | 【待確認】 |
| 無結果時 | 注入兜底句「你想不起相關的事。」 |

### 檢索觸發時機　【推測待確認】

| 時機 | 是否檢索 |
| --- | --- |
| 一般 tick | ✘ 不檢索（省時間） |
| 遇到未在 L1 出現過的角色 | ✔ 以該角色為查詢 |
| 抵達新地點 | ✔ 以地點為查詢 |
| 天神之石事件 | ✔ 以事件內容為查詢 |
| 睡眠反思 | ✔ 以當日摘要為查詢 |

> 每 tick 都跑向量檢索會嚴重拖慢速度。建議只在情境變化時觸發。
