## 1. 物品結構

```json
{
  "item_id": "herb",
  "count": 4,
  "decay": 22,
  "durability": 100
}
```

| 欄位 | 型別 | 範圍 | 說明 |
| --- | --- | --- | --- |
| `item_id` | string | — | 物品代號 |
| `count` | int | ≥ 0 | 數量 |
| `decay` | int | 0–100 | 腐壞值，**100 = 完全腐壞** |
| `durability` | int | 0–100 | 耐久值，**0 = 損毀** |

## 1-1. 效果套用（`effect_*` / `personality_delta`）

物品定義（`Ailley/data/items.json`）用兩種欄位描述「用掉這個物品會發生什麼事」：

- **`effect_<欄位>`**：對應《01》§4-1 的 8 項生理數值（`satiety`／`hydration`／`stamina`／
  `wakefulness`／`hygiene`／`alcohol`／`health`／`injury`），一次性加總套用，套用後照
  `Stats` 原本的夾制規則限制在 0~100。沒寫的欄位視為 0，不影響——這是原本只涵蓋
  `satiety`／`hydration`／`alcohol`／`injury` 4 項的通用化版本，其餘 4 項同一套規則。
- **`personality_delta`**：可選，格式跟睡眠反思產出的 `personality_delta` 完全一樣
  （`{維度: 差值}`，由 `Character.apply_personality_delta()` 統一套用、夾在 0~100）——
  多一個「物品」的觸發來源，語意不變：人格仍然只是緩慢調整的長期特質，不是引擎替
  角色即時貼上的情緒標籤（見《00》原則二／`../CLAUDE.md`「遊戲機制規格：AI 自主性
  自檢」）。現有物品都還沒有填這項，欄位已經可用，等真的有物品設計需要時再填數值。

**刻意不做的事**：沒有「效果持續一段時間才消失」的暫時性 buff，也沒有「改變數值衰減
速度本身」的速率覆寫機制——`eat`／`drink` 的效果都是套用當下立刻生效，之後照
`Stats.SPEC` 原本的 drift 速度自然變化。這兩種機制屬於新的一層設計，不是現有
`effect_*` 命名空間能表達的東西，真的需要時再另外規劃、換一組欄位名稱（例如
`duration_effect_*`／`rate_effect_*`），不會跟現在的一次性效果衝突。

實作見 `Ailley/scripts/character/inventory.gd` 的 `use_item()`（讀 `Stats.SPEC`
動態組出要讀哪些 `effect_*` key，SPEC 加一項數值不用跟著改這支函式）與
`Ailley/scripts/character/character.gd` 的 `eat()`/`drink()`。

### 兩個數值的差別

|  | `decay` 腐壞 | `durability` 耐久 |
| --- | --- | --- |
| 方向 | 越高越糟 | 越低越糟 |
| 隨時間變化 | ✔ 自動上升 | ✘ 只在使用時下降 |
| 適用 | 食物、飲品、獵物、水產、採集品 | 隨身用品 |
| 歸零／滿值時 | 不可食用，`eat` 判定失敗 | 損毀，自動移除 |

| 分類 | 英文 | 使用 `decay` | 使用 `durability` | 說明 |

## 5. 經濟循環

```
        ┌─────────────────────────────────────┐
        │              收入                    │
        │  打獵 → 獵物 → 賣給商鋪              │
        │  採集 → 藥草 → 賣給藥草鋪            │
        │  捕魚 → 魚   → 賣給商鋪              │
        │  演奏 → 路人或玩家給錢                │
        └──────────────┬──────────────────────┘
                       ▼
                  ┌─────────┐
                  │  money  │  預設 300
                  └────┬────┘
                       ▼
        ┌─────────────────────────────────────┐
        │              支出                    │
        │  餐酒館 → 食物、酒                   │
        │  藥草鋪 → 藥品                       │
        │  服裝鋪 → 衣物                       │
        │  工具   → 刀、樂器                   │
        └─────────────────────────────────────┘
```

### 商鋪對應

「收購」欄為**完整版才做**——MVP 兩間店只做販售，見上方 callout：

| 地點 | 收購（完整版） | 販售 |
| --- | --- | --- |
| `loc_herb_shop` | 藥草、野果 | 藥品、藥草湯 |
| `loc_clothing_shop` | 衣物 | 衣物 |
| `loc_tavern` | 獵物、魚 | 食物、飲品 |

### 交易規則

規則 1、2 是**收購**專用——MVP 兩間店只做販售不做收購（MVP 範圍 2026-08-16 拍板；
不承諾未來是否會加，2026-08-19 拍板，見上方 §0 note），這兩條 MVP 不適用，留給完整版；
規則 3、4 已於 2026-08-16 拍板採用，MVP 直接用。

| # | 規則 | MVP |
| --- | --- | --- |
| 1 | 商鋪收購價 = 售價 × 0.5 | 不適用（無收購） |
| 2 | `decay` 越高收購價越低：實際收購價 = 基準 × (100 − decay) / 100 | 不適用（無收購） |
| 3 | `reputation < -50` 時商店拒絕交易——這是社會性限制，`buy` 仍留在 `available_actions` 裡讓 AI 能選，由引擎判定失敗（`reason` 回「老闆看你的樣子不想做你的生意」），不像缺物品／狀態不允許那樣直接從清單過濾掉，見《07》§5 | 適用 |
| 4 | 商鋪庫存與現金為無限，不做商鋪經營模擬 | 適用 |

## 6. 腐壞與耐久

### 6-1 腐壞

```
每 tick：decay += 該物品的腐壞速率

decay ≥ 100 → 標記為腐壞
```

| `decay` | 狀態 | 效果 |
| --- | --- | --- |
| 0–39 | 新鮮 | 正常 |
| 40–79 | 不新鮮 | 食用時 `health` -3（2026-08-16 拍板） |
| 80–99 | 快壞了 | 食用時 `health` -10（2026-08-16 拍板） |
| 100 | 腐壞 | 不可食用，`eat` 判定失敗 |

> `home_storage` 的腐壞速率減半（2026-08-16 拍板）——家裡比背包涼快。
> 

### 6-2 耐久

```
每次使用：durability -= 該物品的耐久消耗

durability ≤ 0 → 損毀，自動從庫存移除
```

損毀時寫入 `last_action_result`：「你的刀在使用中斷掉了。」
