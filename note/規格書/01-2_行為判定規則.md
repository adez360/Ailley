# 01-2_行為判定規則

# 01-2｜行為判定規則

**閱讀對象**：後端組・遊戲邏輯組
**文件性質**：成功率計算契約。技能／體力／運氣類行為的成敗一律由本文件的公式決定，LLM 不參與判定；心智判斷類行為（目前僅 `persuade`）依原則四交由當事人的模型判斷，不適用本文件的擲骰流程，見 §3-1。
**前置閱讀**：《00 設計原則與架構》原則一、原則四

---

## 1. 判定流程

```
LLM 輸出意圖（action / target）
        │
        ▼
┌────────────────────────┐
│ ① 前置檢查              │  目標存在？距離夠近？物品在身上？
└────────────┬───────────┘
             │ 通過                      不通過
             ▼                             │
┌────────────────────────┐                 │
│ ② 計算成功率            │  見 §2          │
└────────────┬───────────┘                 │
             ▼                             │
┌────────────────────────┐                 │
│ ③ 擲骰                  │                 │
└────────────┬───────────┘                 │
      ┌──────┴──────┐                      │
      ▼             ▼                      ▼
   ┌──────┐     ┌──────┐            ┌──────────────┐
   │ 成功  │     │ 失敗  │            │ 直接失敗      │
   └───┬──┘     └───┬──┘            └──────┬───────┘
       │            │                       │
       └────────────┴───────────────────────┘
                    ▼
       ┌────────────────────────────┐
       │ ④ 寫回 last_action_result   │
       │    含中文自然語言失敗原因    │
       └────────────────────────────┘
```

> ⚠️ 技能熟練度系統（`skill_*`）確定不採用。成功率只由 **人格 + 生理狀態 + 環境風險** 決定。
> 
> ⚠️ 本流程圖只適用技能／體力／運氣類行為。`persuade` 不進入②③擲骰步驟，改走 §3-1 的模型判斷機制。

## 2. 通用成功率公式

```
成功率 = 基礎成功率
       + 相關人格參數 × 人格係數
       + (stamina - 50) × 0.2%        ← 體力修正
       - injury × 0.4%                ← 傷勢懲罰
       - max(0, alcohol - 30) × 0.5%  ← 醉酒懲罰
       - max(0, 15 - wakefulness) × 1.2%  ← 睏倦懲罰
       - 環境風險

最終夾制在 5% ~ 95%（永遠留一點意外空間）
```

### 修正項說明

| 修正項 | 計算 | 用意 |
| --- | --- | --- |
| 體力修正 | `(stamina - 50) × 0.2%` | 體力 100 → +10%；體力 0 → -10% |
| 傷勢懲罰 | `injury × 0.4%` | 重傷（80）→ -32% |
| 醉酒懲罰 | `max(0, alcohol - 30) × 0.5%` | 微醺（30 以下）不罰 |
| 睏倦懲罰 | `max(0, 15 - wakefulness) × 1.2%` | `wakefulness` 高於 15 不罰；歸零 → -18%（見 `Ailley/scripts/character/agent.gd::_roll_success()` 的 `sleepy_term`） |
| 夾制 | `clamp(5%, 95%)` | 再強的角色也會失手，再弱的也有機會 |

> [!note] `attack` 必中，不是本節通用成功率公式的一員（P-28，《07》§2-4）
> 本節的成功率公式假設「行為者的能力」對抗某種會失敗的阻力（獵物逃脫、目標警覺、體力耗盡）。`attack` 原本套用同一套公式時，那個阻力隱含的意思是「對方閃避或格擋」——但 MVP 沒有實作任何閃避／格擋機制，沒有東西可以讓命中骰失敗，套用一個對抗不存在系統的機率沒有意義。P-28 因此把 `attack` 定為必中，`人格係數`／`環境風險` 兩欄不適用。等閃避／格擋系統真的存在，才需要回頭給 `attack` 一個有意義的命中率。

> `struggle` 例外一：不是搭在 `haul` 檢查點上由引擎代問的動作——檢查點觸發時，被搬運者（依附者）只收引擎內部通知 `on_dependent_checkpoint()`（基底 no-op，不代問，見《02》§3），要不要掙脫由他自己的下一次決策選擇（`struggle` 在 `IMPLEMENTED_ACTIONS` 白名單裡，見《07》§2-4）。`struggle` 例外二：搬運人數為 2 時，無論其餘修正項為何一律判定失敗，不套用 §2 通用公式與夾制範圍。
>
> `perform` 例外三（2026-08-27 拍板）：跟打獵／採集／偷竊的「單次判定」不同，`perform` 是持續進行的長動作，不是一開始骰一次就定生死——依《02》§3 長動作固定間隔檢查點機制，每次檢查點各自重新套用本節公式，判定「這一段」表演的品質，段與段結果互相獨立。手持 `instrument`（演奏才能觸發本動作的門檻道具）額外在每一段重擲時疊加 +15% 成功率，跟《08》物品效果定義一致。

> [!note] 心智判斷類全庫掃描（原則四，issue #193）
> 除 `persuade` 外，本表其餘行為都不屬於心智判斷類——結果不取決於「另一個角色的心智要不要被說動」。`hunt_small`／`hunt_large`／`gather`／`fish`／`steal`／`struggle` 維持擲骰；`attack` 不套用擲骰，MVP 直接判定必中（理由見上方 `attack` 那則註，跟心智判斷類無關，是閃避／格擋機制還沒實作的緣故）。`perform` 雖然結果受「觀眾」影響，但觀眾通常是不特定的多人、沒有單一明確目標，不像 `persuade` 有唯一可問心智的對象，硬套用 persuade 的機制（挑代表性觀眾當裁判？在場者各自判斷？）是全新的設計問題，且 `perform` 本身尚未實作、沒有真實場景可驗證設計合不合理，這輪維持擲骰，等真正實作、有具體多人互動場景時再重新評估。

## 3-1. `persuade` 判定機制（原則四）

`persuade` 不適用 §2 通用公式，成敗不由引擎擲骰，而是交給被說服者自己的模型判斷（見《00》原則四）。

- **不額外呼叫**：`persuade` 發生當下，引擎只記錄「誰、用什麼理由試圖說服你」為一句事實句（比照《01-3》§3 事實句機制），等被說服者下一次自然發起決策時，隨常駐欄位一起帶給模型，不為此單獨開一次呼叫。
- **模型輸出是否被說動**：被說服者的決策輸出多一個欄位表示是否接受這次說服，欄位語意與資料介接細節見《04》§4-2。
- **不驗證**：模型判定「不被說服」不做二次驗證、不設機率保底，接受「一律拒絕以規避後果」的已知風險。回應省略 `persuaded` 欄位時視同「不被說動」，待回應記錄照常清除，不重複注入同一句事實句（欄位細節見《04》§4-2，實際 schema 接法見 issue #227）。

### 行動說服 vs 純思想說服（issue #227，2026-08-19 拍板）

`persuade` 的說服內容分兩種，由發起時 params 裡的 `proposed_task` 有沒有填自然分流，不另設類型欄位：

- **行動說服**（`proposed_task` 有填，形狀跟一般任務一筆相同）：被說服者輸出 `persuaded: true` 時，引擎把 `proposed_task` 機械式推進被說服者的任務池（跟一般 LLM 任務同一套驗證與仲裁）——說服的「效果」是結構保證的，不需要被說服者的模型自己再想一次要做什麼、也不驗證它想的對不對
- **純思想說服**（`proposed_task` 未填，只有 `reason` 自由文字）：`persuaded: true` 時，`reason` 連同模型自己判斷的 `importance`（0-100）／`valence`（`positive`/`negative`/`neutral`）一起寫進被說服者的記憶（`Memory.add_candidate()`）——變成他之後真的「記得」自己被說服相信了這件事，不強制對應任何具體動作
- 兩種情況 `persuaded: false` 或省略都一律不做任何事，待回應記錄照常清除

**忙碌拒絕**：被說服者已經有一筆待回應記錄時，新的 `persuade` 直接判定失敗（比照 `talk_to()` 的 `TARGET_BUSY`），不覆蓋、不排隊——避免舊記錄被靜默蓋掉、發起者完全不知道自己的嘗試消失。

**範圍界線**：說服目標是玩家（沒有 LLM 決策迴圈，`persuaded` 這條路徑走不通）不在這套機制內，見 issue #305。

## 4. 偷竊完整算式（範例示範）

其他行為請照本節格式展開。完整公式（含環境風險、體力/傷勢/酒精/清醒度修正項）已照
本節數字實作在 `Ailley/scripts/character/agent.gd::_roll_success()`；`fish`／`steal` 兩個動作不在
`Ailley/scripts/ai/ai_schema.gd` 的 `IMPLEMENTED_ACTIONS` 白名單裡，LLM 選不到，公式不會被真實
決策打中——詳見下方 §5 表格第 4 點「現況」。

```text
偷竊成功率 = 35%
           + courage × 0.25%
           + (stamina - 50) × 0.2%
           - injury × 0.4%
           - max(0, alcohol - 30) × 0.5%
           - max(0, 15 - wakefulness) × 1.2%
           - 環境風險（偷竊在 MVP 地點固定 0）
```

睏倦懲罰與環境風險是 §2 通用公式的一部分，這裡一併列出讓範例跟 `_roll_success()` 完全對齊。

> [!note] 沒有「目標警覺度」這一項——2026-08-24 拍板（見《99》P-64）
> 原本設計裡「目標角色 sociability × 0.1%」代表「交際廣的人警覺高」，但這是
> 引擎直接把目標的社交人格值換算成一個警覺度數字、單方面幫她決定「她這時候
> 有多警覺」，被害人本人的模型完全沒有表態機會，跟 PR #489 被拿掉的固定
> trust 公式是同一種《00》原則二/三問題，**已從公式拿掉，不是暫時省略**。
> 成功率只看小偷自己的能力（`courage`／體力／傷勢／酒精），對方警不警覺完全
> 不影響小偷成不成功——影響的是下面「有沒有被發現」，那是另一個獨立問題

### 被目擊判定：走既有 `Vision`／`make_noise()` 偵測管線，不是獨立公式

2026-08-24 拍板（見《99》P-64）：不再用「現場其他角色數×20%－夜間10%」這種
脫離場景的抽象機率，改成跟其他「誰看得到誰、誰聽得到誰」的場合共用同一套
判定——附近角色是否目擊小偷這次行動，看的是他們有沒有真的 `Vision.can_see()`
（視野半徑內、無遮蔽物，不判斷朝向，見 [[視覺感測]]）或收到 `make_noise()`
的聲音廣播，跟角色被看見／被聽見走同一套物理管線，偷竊不另開一條專屬公式。

角色能不能提高自己發現的機率，是他自己的行為（例如靠近可疑方向、或做出
「留意周遭」這類動作提高自己接收 `noise_heard` 的範圍），不是引擎幫他算
一個「警覺值」加成——細節（要不要新增一個「留意周遭」動作）待補，見
《99》P-64。

### 四種結果

| 成功 | 被目擊 | 結果 |
| --- | --- | --- |
| ✔ | ✘ | 東西到手，無人知曉 |
| ✔ | ✔ | 東西到手，`reputation` 下降；目擊者收到一句事實句，對小偷的觀感交給 AI 自己判斷，不寫死關係數值（`relations` 沒有信任這類評價欄位，見《01》§3-1） |
| ✘ | ✘ | 什麼都沒發生，`last_action_result` 記錄失敗原因 |
| ✘ | ✔ | 最慘：東西沒拿到還被看見 |

> 💡 「贏了裡子輸了面子」的第二種結果最有觀察價值。務必確保這個組合會發生。

## 5. 實作備註

| # | 注意事項 |
| --- | --- |
| 1 | 成功率計算只讀 **tick 開始前的快照**，避免同 tick 內互相影響 |
| 2 | 每個行為的失敗原因要寫成中文自然語言，不要用錯誤碼 |
| 3 | 失敗原因要具體到 AI 能調整策略（「現場有兩名目擊者」而非「條件不足」） |
| 4 | **現況**：`_roll_success()` 本身（公式、修正項、失敗原因）已照本節數字完整實作於 `Ailley/scripts/character/agent.gd`，`SUCCESS_PARAMS` 表也已填好 `hunt_small`／`hunt_large`／`gather`／`fish`／`steal`／`perform` 六筆，其中 `hunt_small`／`hunt_large`／`gather`／`perform` 已在 `Ailley/scripts/ai/ai_schema.gd` 的 `IMPLEMENTED_ACTIONS` 白名單裡，resolve() 會真的擲骰；`fish`／`steal` 仍不在白名單，LLM 選不到，公式不會被真實決策打中。`struggle` 雖然在白名單裡，但執行邏輯還沒接上（issue #337）。除攻擊命中率（必中，不擲骰）與治療地點檢查外，其他動作目前尚未實作真正的成敗判定——不在 `SUCCESS_PARAMS` 表上的動作 `_roll_success()` 直接放行 |
| 5 | **2026-08-24 補充**：§3 表格「環境風險」欄（森林危險度／目擊者／觀眾人數修正／搬運人數）目前全部沒有實作——`_environment_risk()` 現在固定回傳 `0.0`，不分動作。之後打獵／採集／表演真的拉進 MVP 開始實作時，這欄每一項都要各自補上真正的計算，不是等結構已經在表格裡就當作已經算好了 |
