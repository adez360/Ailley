## 2. 五條核心原則

### 原則一：LLM 決定「想做什麼」，引擎決定「做不做得到」

AI 輸出的是意圖，不是結果。技能／體力／運氣類行為的成功／失敗由引擎擲骰判定；心智判斷類行為是獨立類別，不適用本條，見原則四。

### 原則二：引擎只給事件，不給情緒

引擎報告**發生了什麼**，AI 決定**這算不算一回事**。

| ✅ 引擎該做的 | ❌ 引擎不該做的 |
| --- | --- |
| 「你已經一整個上午沒和任何人說過話了。」 | 「孤獨度 72」 |
| 「你的東西不見了。」 | 「壓力 +30」 |
| 「你賺到了 30 金幣。」 | 「滿足度 +9」 |

右欄等於引擎替角色決定了它的感受。同一件事，外向的角色三小時就受不了，孤僻的角色一整天無所謂——這個差異必須由 AI 依自己的人設判斷。

這條原則不只管注入 AI 的文字。引擎內部如果用固定公式替一個動作的性質定性（例如判定「這算不算敵對」），然後把定性結果寫進 `relations` 這種會被其他系統當客觀事實使用的數值，本質上跟塞一句「壓力 +30」給 AI 看是同一件事——只是換了個下游。尤其是同一動作在不同情境下語意可能天差地遠時（例如搬運清醒角色，可能善意也可能挾持），引擎更不該用一套公式幫它蓋章，這個定性判斷要交還給當事人自己接下來的行為決定。

### 原則三：欄位存在的唯一理由

> **除了餵給 LLM 讀，引擎自己有沒有拿它算東西？**
> 

有 → 是客觀事實，留。沒有 → 是主觀感受，交給 AI 自己產生。

| 客觀事實（留） | 引擎用途 |
| --- | --- |
| `personality` 10 項 | 成功率公式、記憶衰減率 |
| `state.physical` 8 項 | 成功率修正、死亡判定 |
| `reputation` | 商店拒絕交易、社交申請通過率 |

### 原則四：心智判斷類行為，結果交給當事人的模型自己判斷

行為結果如果取決於「另一個角色的心智要不要被說動／相信／感動」，這種判斷不該由引擎用固定機率蓋過去，要交還給操控那個角色的模型自己決定。這是跟原則一（技能／體力／運氣類，結果與「對方怎麼想」無關，交給引擎擲骰）並列的獨立類別，不是原則一的例外：技能／體力／運氣類公平擲骰沒有問題，但心智判斷類的結果本質上就是「對方怎麼想」，模型自身的判斷力必須有機會真正影響結果（見《10》§B33 多模型交流賣點）。

判斷結果不驗證、不二次判定，比照 `believed`（見《04》）：AI 說了算，接受角色一律回答「不被說動」規避後果的已知風險。

適用範圍逐一列在各行為自己的判定規則裡，不自動套用到所有語意上像「說服」的行為；未經列名的行為維持原則一。目前唯一列名的是 `persuade`（見《01-2》§3）。

### 原則五：玩家與 NPC 的能力對稱

Player 與 Agent 都是 Character 的具體化，能不能執行一個動作只看動作本身的門檻（背包裡有沒有這個物品、體力夠不夠、距不距離夠近……），不看操控者是人還是 AI。新增一個動作或能力時，只要情境上玩家跟 NPC 都可能碰到，兩邊都要接通；只做一邊、把另一邊留成技術負債，本身就是規格沒做完，不是可以之後再說的優化項。

### 三條硬規定

1. LLM 不能宣告自己沒有的東西（物品、金錢、關係）
2. LLM 不能宣告 `state.physical` 的任何數值
3. 所有注入 LLM 的數值必須附中文形容詞，所有失敗必須附中文原因

## 4. 資料分層架構

按「多久變一次」分層。好處：每 tick 只重算 L3、存檔時 L0/L1 幾乎不用重寫、prompt 可分段組裝並命中快取。

```
╔══════════════════════════════════════════════════════════════╗
║  L0  身分層  identity                              永不變      ║
║  ────────────────────────────────────────────────────────    ║
║  id / name / age / gender / appearance[] / character         ║
║  words_to_creator / taboos[] / occupation / created_at       ║
║  → 建角時決定，之後不再變動                                    ║
╠══════════════════════════════════════════════════════════════╣
║  L1  人格層  personality                          幾乎不變     ║
║  ────────────────────────────────────────────────────────    ║
║  10 項引擎參數（0–100）                                       ║
║  → 由 HEXACO 六維轉換產生；睡覺反思 ±3                        ║
║  → ⚠ 引擎專用，不注入 Prompt                                  ║
╠══════════════════════════════════════════════════════════════╣
║  L2  社會層  relations / reputation / economy      慢慢變      ║
║  ────────────────────────────────────────────────────────    ║
║  對每個認識的人見面次數/外觀快取 / 公共名聲 / 金錢 / 庫存      ║
║  → 一天變動幾點                                               ║
╠══════════════════════════════════════════════════════════════╣
║  L3  狀態層  state                                每 tick 變   ║
║  ────────────────────────────────────────────────────────    ║
║  physical 8 / emotion / conditions[] / current_goal          ║
║  today_plan[] / last_action_result / location_id             ║
╚══════════════════════════════════════════════════════════════╝
```

### 各層速覽

| 層 | 區塊 | 欄位數 | 誰寫入 | 是否注入 Prompt |
| --- | --- | --- | --- | --- |
| L0 | `identity` | 9 | 玩家建角 + AI 生成一句話 | 部分（經文字化） |
| L1 | `personality` | 10 | 引擎（轉換 + 反思） | **否** |
| L1 | `hexaco_input` | 6 | 玩家建角，之後唯讀 | **否** |
| L1 | `system_prompt` | 1（字串） | 引擎建角時組裝 | 是（常駐） |
| L2 | `relations` | 每人 2（`met_count`／`appearance_cache`） | 引擎 | 條件式（僅在場者） |
| L2 | `reputation` | 1 | 引擎 | 是 |
| L2 | `economy` | 3 | 引擎 | 條件式 |
| L3 | `state.physical` | 8 | **僅引擎** | 是（附形容詞） |
| L3 | `state.emotion` | 4 | LLM 宣告 + 引擎倒數 | 是 |
| L3 | 其他 `state` | 5 | LLM + 引擎 | 是 |

## 7. 決策循環（事件驅動）

**事件驅動，非輪巡。** tick 只是時間計量，不是決策觸發器（見 §3、《10》§1）。角色各自獨立運作：完成當前動作後才發起下一次決策請求，不是全體角色被同一個 tick 訊號同步喚醒。世界開始時所有角色依序發起第一次請求、進入優先序佇列（對話輪次優先於行程請求）。完整的觸發時序與出隊順序見《10》§5.1，決策來源抽象與職責邊界見《12》。

              │ 角色完成當前動作           │ ◄────────────────────┐
              └────────────┬─────────────┘                       │
                           ▼                                     │
              ┌──────────────────────────┐                       │
