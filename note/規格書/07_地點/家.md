# 家（`home`）

**用途**：睡眠（回復量最大）、家中儲存
**容量上限**：1（《99》P-17 #2 已定案，先開工、實測後再調）

**每個角色各自一間**：`home` 不是單一地點，是每個角色的 `home_location_id`（《01》§1-1）
指到的其中一筆。AI 決策時仍只看到抽象的 `home`（跟其他地點一樣用 `location_id`），
引擎收到目標為 `home` 的動作時，依發起角色的 `home_location_id` 解析成實際座標——
角色之間互不相通，A 的家不是 B 的家（全滿不再是共用，而是動態成長出一間新的；
溢出共用只剩安全閥性質的例外——找不到落點或 DB 寫入失敗時退回共用，見下方
動態成長供給）。

**地圖上放固定幾間房子，建角時系統自動分配**（2026-08-16）：玩家不用選。

**間數動態成長**（issue #751，2026-08-30 拍板提前於 P-58 實作）：房子數量不再
綁 `DEPLOY_CAP` 這個固定人數上限。地圖上永久畫好 5 間靜態家（`loc_home_01`～
`loc_home_05`，issue #391），場上需要更多時（例如 `DEPLOY_CAP` 的 AI 再加上
玩家）系統會即時多長一間出來，不受固定間數限制。

**已實作（issue #391，供給成長見 issue #751）**：`location` 表 lazy-seed
`loc_home_01`～`loc_home_05` 五筆，`CharacterStatePersistence._resolve_home_location()`
round-robin 分配並寫回 `Character.home_location_id`，游標存在獨立的
`home_assignment` 表（單一列，見 `HomeAssignmentSchema.gd`）。`places.gd` 的
`has_for()`／`resolve_for()` 讓 AI／`current_place`／`npc_schedule.json` 仍
只認抽象的 `home`，依角色的 `home_location_id` 轉譯成實際要查的
`loc_home_0N`；`to_ai_place_name()` 負責反向——`resolve_from_position()` 反查
到物理錨點時，事實句與 L3 記憶篩選用的字串收斂回抽象的 `home`，不讓 AI 看到
內部 DB id。5 個 `loc_home_01`～`loc_home_05` Marker2D 已加進
《[[村莊地圖]]》的 `PlaceAnchors`，彼此間距與 `NavGrid` 可達性皆已驗證。

**動態成長供給**：5 間靜態家全滿時，`_grow_home_supply()` 用 `NavGrid`
找一個「錨點格與房屋 7x5 格足跡都可走」、跟現有每一間家距離都超過
`HOME_MIN_SEPARATION`（128px：房子 112x80 碰撞體不能互疊，也要大於
`ACTUAL_PLACE_RADIUS` 的 32px，避開
`resolve_from_position()` 反查坑——見《[[村莊地圖]]》的 PR #727 postmortem）
的落點，動態 instantiate 一棟房屋場景＋在 `PlaceAnchors` 底下加一個
新的 `loc_home_0N` 錨點——錨點在門口的可走格，房屋本體往北收
`DYNAMIC_HOME_ANCHOR_TO_HOUSE`（48px），碰撞箱不蓋住錨點；生成／拆除後
deferred 一幀重建 `NavGrid`（`_schedule_nav_rebuild()`）。`location` 表的
座標存進 `pos_x`／`pos_y`（存的是錨點座標；動態家專用，5 間靜態家的座標
仍只在場景裡，不重複存）。
**角色離開世界**：若牠住的
是動態成長出來的家（編號 > 5），對應的場景節點被拆除、`location` 列標記
`is_active = 0`；5 間靜態家不受影響，本來就是永久場景內容，空出後照舊靠
round-robin 給下一個人。**角色重新進場不保留分配權**：不論原本住哪一間，
下次都是全新的 round-robin／成長分配，不會刻意讓牠沿用被拆除前的那間
（`is_active = 0` 的家過不了沿用檢查，自然失敗）。**讀檔重建**：進世界時
（`main_scene.gd::_ready()`，新遊戲／繼續／回選單再進都會跑到）把 DB 裡
所有仍是 `active` 的動態家重新 instantiate 一次（`_rebuild_dynamic_homes()`），
因為它們的場景節點是純執行期產物，重開遊戲／離開世界後不會自動還原；
autoload 開機的那次 deferred 呼叫撞的是主選單場景（沒有 `place_anchors`／
world），會直接跳過不噴錯。

**既有存檔相容**：`_resolve_home_location()` 不只檢查 DB 的 `location` 表有沒有
這一列，還會驗證值本身符合 `loc_home_NN`（正整數編號，動態成長後沒有固定上限）
的命名格式——issue #391
之前的舊 fallback 值（`home_001` 這類）格式對不上，會被視為無效值、自動重新
分配一個新格式的家，不會卡死也不需要手動遷移。

**分配方式（round-robin）**：`location_id` 命名為 `loc_home_01`、`loc_home_02`……
（供《[[腳本地圖]]》`PlaceAnchors` 對應時採用），依字典序排成順序表，系統維護
一個「下一個嘗試分配的索引」游標，範圍只涵蓋目前 `is_active = 1` 的家（拆除
的動態家在復活前不算在內）。建角時從游標位置沿順序找第一間空房分配，游標移
到該房屋的下一個位置（mod 目前家的總數）。**現有家全滿**：不再是「找不到就
共用」的安全閥，改成 `_grow_home_supply()` 真的長一間新的出來（見上方「動態
成長供給」）——優先復活一間先前拆除、目前 `is_active = 0` 的家（重用編號，
避免拆了又長無止盡往後加號碼），沒有可復活的才開一個新編號（取現有編號的
最小缺口）。**讀檔**：游標本身要存檔（跟房屋佔用狀態一起存），讀檔時直接
恢復。沒有游標欄位的舊存檔，讀檔時預設游標為 0。**新建世界**：游標初始化為
0，5 間靜態家初始皆為空，確保第一次分配結果固定從序列最前面開始。

同居功能（多角色共用一間房子）不在這次拍板範圍內，留到 Phase 3/4，見
《[[99_待規劃項目清單]]》P-58。

## 地點結構

`danger: 0` / `resources: []` / `regen: {}`（2026-08-16 拍板）——家沒有環境危險，也沒有可採集
的資源，欄位定義見《[[07_地點與行動]]》地點資料結構。

`desc: "籬笆圍出的小院子，南邊出口正對著藥草鋪的門，走幾步就到。"`（依《[[村莊地圖]]》實際佈局：
家的院子南側缺口 `(-8,-2)` 與 `herb_shop` 院子北側缺口 `(-7,3)` 幾乎同一條垂直線上，
兩院子入口互相正對）
