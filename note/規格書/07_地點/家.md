# 家（`home`）

**用途**：睡眠（回復量最大）、家中儲存
**容量上限**：1（《99》P-17 #2 已定案，先開工、實測後再調）

**每個角色各自一間**：`home` 不是單一地點，是每個角色的 `home_location_id`（《01》§1-1）
指到的其中一筆。AI 決策時仍只看到抽象的 `home`（跟其他地點一樣用 `location_id`），
引擎收到目標為 `home` 的動作時，依發起角色的 `home_location_id` 解析成實際座標——
角色之間互不相通，A 的家不是 B 的家（5 間全滿時的溢出共用是例外，見下方安全閥）。

**地圖上放固定幾間房子，建角時系統自動分配**（2026-08-16）：玩家不用選。

**間數的產生規則**（2026-08-20 拍板，見 issue #370）：房子間數 = 房主建立世界時設定的人數
上限 N，不是寫死的數字。**MVP／Phase 2 階段這個 N 是固定 5**，對應《10》B21 的
`DEPLOY_CAP`（世界內 AI 角色同時投放上限，預設 5）。
系統不會依任意 N 動態生成房子——若房主未來把人數上限調高到超過目前地圖手動佈置的間數
（例如 10），屬於地圖動態擴張的範疇，MVP／Phase 2 不支援，見下方 P-58。

**已實作（issue #391）**：`location` 表 lazy-seed `loc_home_01`～`loc_home_05`
五筆，`CharacterStatePersistence._resolve_home_location()` round-robin 分配並
寫回 `Character.home_location_id`，游標存在獨立的 `home_assignment` 表（單一
列，見 `HomeAssignmentSchema.gd`）。`places.gd` 的 `has_for()`／`resolve_for()`
讓 AI／`current_place`／`npc_schedule.json` 仍只認抽象的 `home`，依角色的
`home_location_id` 轉譯成實際要查的 `loc_home_0N`；`to_ai_place_name()` 負責
反向——`resolve_from_position()` 反查到物理錨點時，事實句與 L3 記憶篩選用的
字串收斂回抽象的 `home`，不讓 AI 看到內部 DB id。5 個 `loc_home_01`～
`loc_home_05` Marker2D 已加進《[[村莊地圖]]》的 `PlaceAnchors`，彼此間距與
`NavGrid` 可達性皆已驗證。

**5 間全滿時的安全閥**：玩家本身也走 `_ensure_npc_record()` 要一間家，
`DEPLOY_CAP=5` 的 AI 角色再加上玩家，理論需求可能達到 6，超過 5 間的供給——
`_assign_next_home_location()` 這時不會讓整筆 npc 建立失敗（`home_location_id`
在 schema 是 `NOT NULL`，失敗會讓該角色的 state/wallet/inventory 同步永久卡死），
而是退回跟游標當下那一間溢出共用，`push_warning` 記錄。**這不是同居功能的
實作**，同居仍照下方拍板留在 Phase 3/4——這裡純粹是容量耗盡時避免整套同步斷掉
的防呆。

**既有存檔相容**：`_resolve_home_location()` 不只檢查 DB 的 `location` 表有沒有
這一列，還會驗證值本身符合 `loc_home_01`～`loc_home_05` 的命名格式——issue #391
之前的舊 fallback 值（`home_001` 這類）格式對不上，會被視為無效值、自動重新
分配一個新格式的家，不會卡死也不需要手動遷移。

**分配方式（round-robin）**：5 間房子各自的 `location_id` 命名為 `loc_home_01`～`loc_home_05`
（這裡新訂，供《[[腳本地圖]]》`PlaceAnchors` 對應時採用），依字典序排成固定順序表，系統維護
一個「下一個嘗試分配的索引」游標。建角時從游標位置沿固定順序找第一間
空房分配，游標移到該房屋的下一個位置（mod N）。**角色刪除**：騰出的房屋標記為空，游標不
回退，下次巡覽自然會再排到它，避免同一間房子被連續重複塞爆。**讀檔**：游標本身要存檔（跟
房屋佔用狀態一起存），讀檔時直接恢復，不能靠「已佔用房屋中最大索引 + 1」反推——刪除角色
會在佔用序列中留下空洞，最大索引不等於真正的游標位置（例：佔用 0/1/3，游標其實停在 2，
最大索引反推會算成 4）；世界裡沒有任何角色時「最大索引」本身也沒有定義。沒有游標欄位的
舊存檔，讀檔時預設游標為 0。**新建世界**：游標初始化為 0，所有 `loc_home_01`～`loc_home_05`
初始皆為空，確保第一次分配結果固定從序列最前面開始。

地圖動態擴張（人數上限中途調高）與同居功能（多角色共用一間房子）不在這次拍板範圍內，
留到 Phase 3/4，見《[[99_待規劃項目清單]]》P-58。

## 地點結構

`danger: 0` / `resources: []` / `regen: {}`（2026-08-16 拍板）——家沒有環境危險，也沒有可採集
的資源，欄位定義見《[[07_地點與行動]]》地點資料結構。

`desc: "籬笆圍出的小院子，南邊出口正對著藥草鋪的門，走幾步就到。"`（依《[[村莊地圖]]》實際佈局：
家的院子南側缺口 `(-8,-2)` 與 `herb_shop` 院子北側缺口 `(-7,3)` 幾乎同一條垂直線上，
兩院子入口互相正對）
