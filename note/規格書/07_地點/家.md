# 家（`home`）

**用途**：睡眠、家中儲存
**容量上限**：1（《99》P-17 #2 已定案，先開工、實測後再調）

**每個角色各自一間**：`home` 不是單一地點，是每個角色的 `home_location_id`（《01》§1-1）
指到的其中一筆。AI 決策時仍只看到抽象的 `home`（跟其他地點一樣用 `location_id`），
引擎收到目標為 `home` 的動作時，依發起角色的 `home_location_id` 解析成實際座標——
角色之間互不相通，A 的家不是 B 的家。

**供給完全動態，地圖上沒有畫死的家**（issue #825）：`level.tscn` 不再有任何
`loc_home_*` 錨點或房屋節點。每個進場的角色由引擎替他長一間、離場時拆掉，
房子數量不綁 `DEPLOY_CAP` 這個人數上限。玩家不用選家。

**已實作**：`CharacterStatePersistence`
（`_resolve_home_location()` → `_assign_next_home_location()` → `_grow_home_supply()`）
在角色第一次同步時分配並寫回 `Character.home_location_id`，round-robin 游標存在
獨立的 `home_assignment` 表（單一列，見 `HomeAssignmentSchema.gd`）。`places.gd`
的 `has_for()`／`resolve_for()` 讓 AI／`current_place`／`npc_schedule.json` 仍
只認抽象的 `home`，依角色的 `home_location_id` 轉譯成實際要查的 `loc_home_NN`
錨點；`to_ai_place_name()` 負責反向——`resolve_from_position()` 反查到物理錨點時，
事實句與 L3 記憶篩選用的字串收斂回抽象的 `home`，不讓 AI 看到內部 DB id。

**動態成長供給**：現有 `is_active = 1` 的家全部被占用時，`_grow_home_supply()`
用 `NavGrid` 找一個「錨點格與房屋足跡都可走」、跟現有每一間家距離都超過
`HOME_MIN_SEPARATION`（160px：房子 wall 圖層 128x112 碰撞體不能互疊、中間還要
留一格走道，也要大於 `ACTUAL_PLACE_RADIUS` 的 32px 以避開 `resolve_from_position()`
反查坑——見《[[村莊地圖]]》的 PR #727 postmortem）的落點。搜尋起點：已有家時
用第一間現有的家，一間都還沒有時從涼亭（`pavilion`）錨點起（角色本來就都投放
在涼亭）；搜尋半徑上界 `HOME_PLACEMENT_MAX_RADIUS`（60 格）。
找到落點後動態 instantiate 一棟房屋場景，並在 `PlaceAnchors` 底下加一個同名
`loc_home_NN` 的 `Area2D` 錨點（帶 `CollisionShape2D`，`resolve_from_position()`
反查才認得——比照舊靜態家的錨點形狀）。房屋擺成 `Door` 子節點正好落在錨點
北邊一格；生成／拆除後 deferred 一幀重建 `NavGrid`（`_schedule_nav_rebuild()`）。
`location` 表的座標（錨點座標）存進 `pos_x`／`pos_y`。

**房屋外觀**：依 `loc_home_NN` 編號奇偶交替——奇數用 `scenes/houses/house_001.tscn`、
偶數用 `house_002.tscn`（`_home_scene_path()`）。兩種格局讓村莊看起來有變化；
重開遊戲後靠同一個編號推回同一棟。

**角色離開世界**：對應的房屋節點與錨點被拆除、`location` 列標記
`is_active = 0`。**角色重新進場不保留分配權**：不論原本住哪一間，下次都是
全新的分配（`is_active = 0` 的家過不了沿用檢查，自然失敗）。**讀檔重建**：
進世界時（`main_scene.gd::_ready()`，新遊戲／繼續／回選單再進都會跑到）把 DB
裡所有仍是 `active` 的家重新 instantiate 一次（`_rebuild_dynamic_homes()`），
因為它們的場景節點是純執行期產物，重開遊戲／離開世界後不會自動還原；
autoload 開機的那次 deferred 呼叫撞的是主選單場景（沒有 `place_anchors`／
world），會直接跳過不噴錯。

**既有存檔相容**：migration 13 把舊 DB 裡殘留的 home 列（issue #391 seed 的
`loc_home_01`～`05`、以及 #825 前期用佔位美術生成的動態家）全部標
`is_active = 0`；進場後由 `_grow_home_supply()` 用新的 `house_001/002` 交替重長，
舊編號經 `_reactivatable_home_location_id()` 從 01 開始復用。
`_resolve_home_location()` 另外驗證值本身符合 `loc_home_NN`（正整數編號、無上限）
的命名格式——issue #391 之前的舊 fallback 值（`home_001` 這類）格式對不上，
會被視為無效值、自動重新分配。

**分配方式（round-robin）**：`location_id` 命名為 `loc_home_01`、`loc_home_02`……
依字典序排成順序表，系統維護一個「下一個嘗試分配的索引」游標，範圍只涵蓋目前
`is_active = 1` 的家（拆除的家在復活前不算在內）。分配時從游標位置沿順序找第一間
空房，游標移到下一個位置（mod 目前家的總數）。**現有家全滿**：改成
`_grow_home_supply()` 真的長一間新的出來（見上方「動態成長供給」）——優先復活
一間先前拆除、目前 `is_active = 0` 的家（重用編號，避免拆了又長無止盡往後加
號碼），沒有可復活的才開一個新編號（取現有編號的最小缺口）。找不到落點或
`_create_or_reactivate_home()` DB 寫入失敗時，退回共用一間現有的 active 家——
只剩這一種安全閥性質的溢出共用，避免 `home_location_id` 留空撞 `NOT NULL`。
**讀檔**：游標存在 `home_assignment` 表，讀檔直接恢復；沒有游標欄位的舊存檔
預設為 0。

同居功能（多角色共用一間房子）不在拍板範圍內，留到 Phase 3/4，見
《[[99_待規劃項目清單]]》P-58。

## 地點結構

`danger: 0` / `resources: []` / `regen: {}`（2026-08-16 拍板）——家沒有環境危險，也沒有可採集
的資源，欄位定義見《[[07_地點與行動]]》地點資料結構。

`desc: "籬笆圍出的小院子，南邊出口正對著藥草鋪的門，走幾步就到。"`（依《[[村莊地圖]]》實際佈局：
家的院子南側缺口 `(-8,-2)` 與 `herb_shop` 院子北側缺口 `(-7,3)` 幾乎同一條垂直線上，
兩院子入口互相正對）

## 可用行動

- `sleep` —— 回復量只看 `duration` 分級，不看地點（分級定義見《[[07_地點與行動]]》§2-3；可用地點未決，見《[[99_待規劃項目清單]]》P-74）
- 通用行動（`move` / `idle` / `talk`）一律可用，見《[[07_地點與行動]]》§5
