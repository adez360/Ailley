# 交接：雲端／本地模型一致性正式對照

> 用途：把「雲端模型跟本地模型跑同一套架構，輸出品質差多少」這條線獨立交給另一人/另一個專案接手，不需要碰重複退化修復（`batch_regen`）那條主線。

## 目標

驗證「角色卡／prompt／洩漏偵測／OpenCC」這整套架構，是不是只在本地 Qwen2.5-7B-Instruct-Q4_K_M 上有效，換一個完全不同的雲端模型是否也能撐起同樣的遊戲邏輯與內容品質。最終要能回答：如果之後要接雲端付費 API 當正式後端（或當本地推論之外的備援），品質/穩定性/成本上划不划算。

## 目前狀態（已完成的部分）

- **架構已存在**：`poc/director_poc_cloud.py`，跟本地版 `director_poc.py` 共用同一份 `director_system_prompt.txt`／世界觀／角色卡邏輯，唯一差異是改打 OpenRouter 的 `/chat/completions`（OpenAI 相容格式），因為 OpenRouter 免費模型沒有 GBNF grammar 可用，改成 prompt 尾端強調輸出格式＋事後用 `_extract_json()` 容錯解析 JSON。
- 目前預設模型：`openai/gpt-oss-20b:free`（可用環境變數 `AILLEY_CLOUD_MODEL` 換其他 OpenRouter 免費模型；上一次選用的 `meta-llama/llama-3.1-8b-instruct:free` 已下架，查詢可用免費模型列表要打 OpenRouter 的 `/api/v1/models`）。
- `.env`（`poc/.env`，內容 `OPENROUTER_API_KEY=sk-or-v1-...`）已設定好、已在 `.gitignore` 排除，不用重新申請。
- **已跑過的零星測試**（都不是「同角色配對」的直接對照，是各自獨立跑的）：
  - 4 場純雲端測試（莫古 vs 班、索菲 vs 傑克、莫古 vs 傑克 × 2）：速度慢很多（63-122 秒／6 回合 vs 本地 ~14 秒／10 回合，推測是免費層限流/排隊）；JSON 穩定度 4/4 成功；簡體污染 0/4（樣本太小不能下結論）；**跨陣營洩題率明顯偏高**（4 場裡 3 場、共 4 次事件，本地過去 7-8 場才 1-2 次）——這個雲端模型執行 `bluff` 戰術詐對方時，常常直接講出對方真正的核心能源名稱當誘餌，比本地模型的「隨口帶到」更系統性，推測資訊隔離做得更弱。
  - 「tactic none」「豐富世界觀」兩個實驗方向，因為桌機當時斷線，也是先在雲端模型上測的（`test_tactic_none.py`／`test_world_lore_v2.py`），後來確認雲端測試那批的 JSON 失敗率（5/7、4/5 成功）是「沒有 GBNF grammar 保底」造成的，跟本地版重測後 50/50 全過形成對比——**這代表雲端模型本身的生成穩定度顯著低於本地＋grammar 鎖定的組合，是先天限制，不是能靠 prompt 調校解決的**。
- **成本調查已完成**（見主筆記「雲端付費 API 現況調查」章節），如果之後要換成付費雲端 API 當正式對照組，建議：免費長期測試用 **Google Gemini 2.5 Flash-Lite/Flash**（官方免費額度，比 OpenRouter 社群贊助免費層穩定，不會突然下架）；要測「能力天花板」用 **Claude Sonnet 5**。100 場量級的呼叫成本都在幾塊美金以內，錢不是瓶頸。

## 待辦事項

1. **「同角色配對」直接對照測試（核心，還沒做過）**：用同一組固定角色卡（`characters.py` 的 `FIXED_CAST_RED`/`FIXED_CAST_BLUE`）、同樣的配對，本地跑一次、雲端跑一次，逐場比較：
   - 內容品質（劇情連貫性、角色驅動力/關係背景有沒有被吸收）
   - 戰術分布是否合理（是否卡在單一 tactic）
   - 洩漏偵測正確性（自評 vs 文字比對是否一致）
   - 簡體污染率（樣本數要夠大，之前 0/4、0/4 都太小）
   - 跨陣營洩題率（這是目前唯一已經看到明顯差異的指標，需要更大樣本確認不是巧合）
   建議至少 10-15 組配對才有意義（比照 MAX_TURNS 決策用 15v15 的樣本量）。
2. **雲端版沒有續寫（continuation）能力**：目前只有 `director_poc_cloud.py`（對應本地的 `director_poc.py`，單次生成），**沒有 `continue_director_poc_cloud.py`**（對應本地的 `continue_director_poc.py`）。如果要測試雲端模型在長鏈續寫下的重複退化情況（本地這條主線目前最頭痛的問題），需要先補這支腳本——架構可以直接照抄本地版的 `continue_director_poc.py`，只把 `call_director()` 換成雲端版 `director_poc_cloud.py` 裡已經寫好的 OpenRouter 呼叫＋`_extract_json()` 容錯解析邏輯即可，兩邊都已經有現成的實作可以直接拼接，不用從零設計。
3. **免費模型的下架風險要有應對**：`AILLEY_CLOUD_MODEL` 環境變數已經支援換模型，但沒有一份「目前可用的 OpenRouter 免費模型清單＋各自已知問題」的紀錄，建議測試時一併把這份清單整理進筆記，之後模型又下架時可以快速切換，不用重新踩一次坑。
4. **決定要不要換成官方付費免費額度**（Gemini 2.5 Flash-Lite/Flash）取代 OpenRouter 免費層，換掉的話 `director_poc_cloud.py` 的 API 呼叫格式要跟著改（Gemini 的 API 格式跟 OpenAI 相容格式不同，`_extract_json()` 那段容錯解析邏輯可能還能沿用，但 request/response 結構要重寫）。

## 初步計畫（建議執行順序）

1. 先補 `continue_director_poc_cloud.py`（待辦 2），這樣才能讓雲端版也跑「MAX_TURNS=6 起始 + 續 5 輪疊到 36 回合」的同一套長鏈驗證方法論，跟本地資料直接可比。
2. 用現有的 `openai/gpt-oss-20b:free` 先跑一輪「同角色配對」直接對照（待辦 1），10-15 組，量化四個指標（內容品質人工評分／戰術分布／洩漏偵測正確性／跨陣營洩題率），確認上面列的「跨陣營洩題率偏高」是不是穩定現象。
3. 視結果決定要不要跳去測付費 API（待辦 4）——如果免費層品質已經差到沒有參考價值，就沒必要繼續在免費層上疊測試，直接跳到小規模付費 API 測試（例如 Gemini 2.5 Flash-Lite 免費額度內就能測，不必等到要花錢的 Sonnet）。
4. 整理最終結論：雲端模型（不論哪個）能不能撐起這套遊戲邏輯，如果不能，具體卡在哪個環節（JSON 穩定度／資訊隔離／續寫重複），寫回主筆記 `POC 紀錄 - 導演模式 B.md`。
