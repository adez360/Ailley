## 二、重大發現：團隊自己的實驗結論，可能跟新規格打架

`memory_store.py` 的程式碼註解明確寫著：

> 評分公式**刻意不含相關性（embedding）項**——`poc_mode_a/dialogue_ping_pong_memory_embed.py`
> 已經驗證過**相關性檢索會強化對話卡住/重複的傾向**，這裡不重蹈覆轍。

而新規格書 **03 §B-5** 的檢索公式是：

```
檢索分數 = 語意相關度 × 0.5 + (importance/100) × 0.3 + 新鮮度 × 0.2
```

**語意相關度佔了一半權重，正是團隊自己測試過會導致對話卡住/重複的東西。**
這不是猜測的落差，是團隊自己做過實驗、寫進程式碼註解的明確結論，跟 Ru 寫的正式規格
直接衝突。**建議在採用規格書之前先跟 Ru 對一下**，避免正式版重新踩一次已經踩過的坑。

## 三、其他具體要對齊的落差

1. **情緒種類完全不同**：POC 是 `excited/happy/in_love/terrified/burnout/angry/sad/neutral`
   （8個），規格書 02 是 `joy/anger/sadness/fear/disgust/surprise/affection/calm`（8個）——
   數量一樣但種類不同，要決定沿用哪一套
2. **人格模型**：POC 6維（勤勉/膽識/社交/道德/情緒穩定/浪漫），規格書 10維（多了好奇心/
   記仇度/貪婪/誠實度）＋ HEXACO 6滑桿轉換層，POC 現有5個角色卡要重新對照轉換
3. **命名慣例**：`enums.py` 裡 38個動作、12個地點**完全沒有前綴**（`ATTACK`、`TAVERN`），
   規格書要求 `npc_`/`loc_`/`item_` 前綴
4. **甘道夫石命名**：`enums.py` 還叫 `GANDALF_STONE`，規格書 07 §1-1 明確要求正式名稱
   改「天神之石」——這條最小最好改，優先處理
5. **攻擊/治療數值是寫死常數**：POC 攻擊固定60%命中率（不受人格影響）、治療固定40元
   回50血；規格書07§4是「人格+生理+環境」完整公式，08§3是「藥材售價×1.5」浮動公式
6. **舉報/抓捕/洗心革面所在 POC 裡完全沒有機制效果**——`enums.py` 裡有這些字，但沒有
   任何程式碼真的處理它們；規格書 07/09 給了完整機制，這塊是純補完，不是衝突
7. **`inventory[]`/`background`/`incarcerated`/`ex_convict`/`vigilant` 這幾個欄位在 POC
   資料模型裡存在但完全沒有邏輯讀寫**——規格書08（物品）、01（identity的character欄位
   取代background）分別把這些補齊
8. **死亡機制過去是「懸而未決」的問題**：舊筆記〈開放問題與待決策〉明確寫「死亡是否
   永久/會不會重生」還沒決定——**規格書09已經給出明確答案**（永久死亡+屍體+墓園），
   可以視為這個懸案正式解決了

## 五、規格書沒有涵蓋、但舊筆記裡有規劃的東西

- **全局事件系統**（天氣/災難，玩家的「神之力」互動）——9份新規格都沒提到

互動層的東西還沒排進來，不是被砍掉，是還沒寫。

## 六、DPO 訓練資料能不能沿用（另見主線 POC 紀錄的詳細討論）

現有 1875+1881 筆資料綁死在 POC 現行中文字串 schema 上，一旦改成規格書要求的
英文 enum+結構化物品，prompt 就不是模型實際會看到的東西，**不能直接拿去訓練**。
但蒐集/生成方法論（用連續失敗自動挖 rejected、按角色人格路由生成 chosen）可以
沿用；已驗證的行為結論（模型不會主動從生理需求切到工作賺錢、巢狀分類會讓資源
匱乏時卡死等）不管換什麼 schema 應該還是同樣的模型傾向，可以指導新資料要蒐集
什麼情境。

## 七、使用者決定（2026-08-07）：整體採用 Ru 版規格，記憶檢索例外

**原則：除了記憶檢索，其餘全部往 Ru 的正式規格書對齊。** 不自己另創一套。

**記憶檢索的例外範圍要縮小**：不是整個 03 都不採用，只排除「語意相關度」這一項。
規格書 03 的五層 L0-L4 分層、重要度公式（§B-4）、遺忘/壓縮規則（§B-6）POC 都沒有
實測反對過，這些照樣採用；真正衝突的只有 §B-5 檢索分數公式裡「語意相關度×0.5」
這一項——改成拿掉這項或大幅降權，只用「重要度+新鮮度」排序，其餘照抄規格書。

**這個偏離要主動告知 Ru/夏，不能自己默默決定**：如果組員照規格書 03 的公式去
實作後端，這邊卻自己換掉檢索公式，之後串接會對不上（他預期的排序邏輯跟我們
實際跑的不一樣）。要讓「拿掉語意相關度」變成團隊共識後的修正，附上
`memory_store.py` 註解裡記錄的實測依據（`dialogue_ping_pong_memory_embed.py`
驗證過相關性檢索會讓對話卡住重複），不是暗自的技術債。

## 九、通訊協議決定：HTTP（2026-08-07）

使用者確認 Godot 端跟 AI 決策後端的通訊協議走 **HTTP**（不是 WebSocket／gRPC／
其他）。**這條不需要額外動作**——現有 `server.py` 本來就是 FastAPI 寫的 HTTP
API（`POST /decide`，走 Tailscale 網段），架構已經對上，不用改。
