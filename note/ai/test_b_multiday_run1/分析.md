# Test B 多角色多日測試：全滅分析

本地測試專用（`worktree-test-decision-trace` 分支，未上 GitHub）。延續
[[../test_a_runs/分析.md|Test A]] 最後留的「之後應該補一次附近有其他角色的
對照測試」，這次是三隻角色（AI2、ai3、ABC）同時存在、`llm_decision_enabled=true`
的多日真實 LLM 測試，中途玩家有手動介入過幾次。原始 JSONL 在同目錄
`run1.jsonl`（377 行，涵蓋到遊戲第 6 天）。

## 結果：三隻全部死亡，且都死在第 3-4 天

| 角色 | 死亡時間 | 死因 | log 是否記到 last_words |
| --- | --- | --- | --- |
| AI2 | 第 3 天（遊戲內墓碑顯示，log 無對應事件） | 未知（同上） | **沒有**——log 裡完全沒有 AI2 的 `last_words`／`petrified` 事件 |
| ai3 | Day4 01:42 | 傷重昏迷，始終無人相救 | 有，遺言留空 |
| ABC | Day4 10:01 | 傷重昏迷，始終無人相救 | 有，「我本來以為這裡的人會伸出援手，誰知最後還是孤獨離世。」 |

死前快照三隻高度一致：health 命懸一線、hunger 極度飢餓、thirst 脫水、
sleepiness 睏到撐不住同時並發——多重生理指標一起崩潰，且全程沒有任何
角色（含玩家）介入急救。

AI2 的墓碑文字是「無名基碑：無人知曉他是誰」——跟牠整場測試「整天沒人
說話」的社交孤立狀態高度吻合，但牠的死亡完全沒有被 `TestRunLogger` 記錄
到。查證：`TestRunLogger` 當時掛的四個出口（`AIService.request()`／
`_select()`／`_log_task_ended()`／`Character.spoke`）全部是死亡連帶觸發
的間接動作，沒有一個掛在 `Character._die()` 本身——AI2 死亡當下
`last_words` 的 LLM 呼叫沒有觸發成功（研判撞到額度／冷卻），四個間接
點因此全部漏記，不是繞過了哪個分支，是這四個出口本來就沒涵蓋死亡事件
源頭（issue #805）。已在 `test_run_logger.gd` 補上 `log_death()`，直接
掛在 `_die()` 呼叫點，記錄不再依賴 `last_words` 是否問到 LLM；已用
`game_eval` 觸發實際死亡實測驗證寫入 JSONL 正確，#805 已關閉。

## 呼應先前的分析結論

- 這次死亡模式跟 Test A 觀察到的「社交敘事蓋過生理危機」是同一套機制的
  延續：三隻在死前都留下大量「好寂寞、想找人聊天」的 reasoning，即使
  當下的生理數值已是各項最差標籤。
- 已對應開出 issue #796（決策迴圈可能永久卡死）、#797（社交衰減閾值該
  隨 #731 生理衰減調慢一起調）、#798（視野範圍太小＋wander 未被當作
  備援選中）——這次全滅結果是這幾個已知問題疊加的具體後果。

## 尚待決策

- ai3 的人格 prompt 裡仍殘留一組 `' OR 1 = 1` SQL injection payload（見
  `run1.jsonl` 內 ai3 的 `last_words` 呼叫），尚未決定公開揭露方式，
  安全性 issue 還沒開。
- 這次測試證明「多重生理危機＋零社交介入」會在 3-4 天內導致角色死亡，
  之後若要測試存活情境，應該安排至少一次玩家或其他角色的主動介入
  （餵食／對話）作對照。
