# reasoning 字數上限實驗（issue #418）：100 字 vs 200 字

## 結論

100 字組（`MAX_REASONING_CHARS`）500 輪累計「連續兩次選同一動作」重複率為 **32.7%**（二項常態近似範圍 28.6%–36.8%，假設獨立，僅供參考），200 字組為 **39.3%**（二項常態近似範圍 35.0%–43.6%，假設獨立，僅供參考）。**這個差異僅供參考，不宣稱統計顯著**：每組是單一連續 500 輪軌跡（後一輪的 `state_before` 由前一輪動作的恢復效果決定），相鄰輪次的 `is_repeat` 觀測彼此不獨立，不能直接套用假設樣本獨立的兩比例 z 檢定或常態近似區間（見下方「統計方法」的說明與限制）。兩組失敗率皆為 0/500。

兩組的 reasoning 實際長度都遠低於各自的字數上限，且**沒有任何一筆輸出達到上限**（100 字組最長 52 字、200 字組最長 61 字，見下方統計表的長度分布），代表 100 字的限制本身**不是**靠「逼模型硬生生截斷因果鏈」壓低重複率——兩組都還有大量餘裕沒用完，也沒有輸出被硬性截斷。差異更可能來自：更緊的字數上限讓模型傾向給出更直接、更少枝節的一句話結論（見下方人工抽查樣本），而 200 字組常常多寫一句與決策無關的補述（例如重複強調「當前沒有可見人物」），稀釋了因果鏈的聚焦程度，但沒有實質降低下一輪選擇同一動作的機率。

另外一個值得注意的現象：200 字組的重複大量集中在 `move_to`（149 次裡有 77 次是重複，占全部重複的 39.3%）；100 字組雖然 `move_to` 也是重複大宗，但 `idle`／`eat` 的重複份量更平均分散（idle 23.9%、move_to 27.6%、eat 20.9%）。合理推測是：本次實驗沒有給任何 `context.visible`／`context.pool`，「四下無人、無事可做」的情境本身就容易讓模型連續選同一種「先去外面看看」的動作，200 字組的餘裕反而讓它更常把這個理由寫成一整段近似的敘述，收斂到同一個 `move_to` 決策。

**建議：維持 `MAX_REASONING_CHARS := 100`，不要改回 200。** 本次實驗至少在「無 visible／無 pool」這種較空曠的情境下，100 字上限的重複率較低、reasoning 沒有被截斷、也沒有觀察到失敗率上升或內容明顯劣化（見下方人工抽查）——但如上所述，這是單一軌跡的描述性觀察，不是統計顯著的結論。若之後想進一步驗證，除了針對有 `context.visible`（有人可互動）或有 `context.pool`（已有排程任務）的情境另外補測，也應該用多條獨立軌跡（不同隨機種子／起始狀態）取代單一 500 輪連續軌跡，才能套用兩比例檢定或改用 cluster/bootstrap 方法得到有效的顯著性結論。

## 方法簡述

- 呼叫次數：每組 500 輪，共 1000 次 LLM 呼叫，模型與 endpoint 讀自本機 `ai_config.json` 的 `default_provider`。
- 模擬邏輯：`run_experiment.py` 用固定衰減公式（`satiety` -8、`stamina` -6、`fun` -5、`hygiene` -4、`social` -5 每輪）驅動一個簡化版 stats 迴圈，每輪把 `state_before` 丟給模型，模型回傳的第一個 task 的 action 拿來套用對應的恢復效果（`eat`→`satiety`+40、`rest/nap/sleep`→`stamina`+40、`wash`→`hygiene`+40、`talk/murmur/shout/give/persuade`→`social`+20），作為下一輪的 `state_before`。時間從 00:00 起每輪 +30 分鐘遞增，`current_action` 傳回上一輪選中的 action。
- 兩組的 system prompt 唯一差異是 `{cap}` 帶入 100 或 200，並同步套用到 JSON schema 的 `reasoning.maxLength`。
- 與 `poc_village_sim` 原始方法論的差異：**這次沒有加真人格 system prompt 前綴**（沒有姓名以外的個性描述、沒有 few-shot 範例），`context.visible`／`context.pool`／`context.today_plan`／`context.fact_lines`／`context.memory` 全程留空，目的是把變因收斂到「reasoning 結構上限」單一因子本身的效果，不摻雜人格或情境豐富度的干擾。因此本次數字反映的是「最空曠情境下」的重複率，不代表有豐富 visible/pool 時的實際遊戲表現。
- 重複率定義：第 i 輪（i>0）選中的 action 是否等於第 i-1 輪選中的 action；round 0 沒有前一輪可比，不計入分母。
- 重現性：`run_experiment.py`／`analyze.py`／原始資料（`raw_100.jsonl`、`raw_200.jsonl`）依專案 `.gitignore` 慣例不進版控，只留這份報告，三者實際跑過的版本存於本機 `note/ai/reasoning_cap_experiment/`（腳本 git blob hash `445b05e73131b11d921f6b8a0a22657ff8442c6a`）。實際使用的 `default_provider`／模型名稱沒有寫進原始資料，只能追溯到讀取自本機 `ai_config.json`（見上一項）；若要嚴格重現，需另外記下當時的 provider 設定。
- 統計方法與限制：重複率的區間用二項分布常態近似 `p ± 1.96·sqrt(p(1-p)/n)` 計算，**不是統計意義上的 95% 信賴區間**，只標示為「二項常態近似範圍（假設獨立，僅供參考）」。**兩組各自只跑了一條連續 500 輪軌跡**（每輪的 `state_before` 由前一輪動作的恢復效果決定，不是重新抽樣的獨立起始狀態），相鄰輪次之間存在序列相關，不滿足常態近似與兩比例 z 檢定都要求的樣本獨立假設，因此本報告**不採用**兩比例 z 檢定的顯著性結論，這個獨立性限制同樣適用於下方統計表列出的範圍——那只是點估計搭配的描述性參考範圍，不是真正的信賴區間，也不宣稱組間差異達統計顯著。
