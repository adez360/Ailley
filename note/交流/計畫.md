# 計畫

[[草案]] 七條拍板之後的方向與執行順序。
全專案的既有決策在 [[決策]]，評估過程在 [[草案決策]]。

## 一句話

```
（進行中：LLM 對話） → 存檔 → 生活空間 → AI 模式 → 多人
```

四個階段接在正在做的 LLM 對話之後。
存檔排第一是因為它同時是共用存檔與記憶系統的前置，做一次解兩件事；
多人排最後是因為在存檔與生活空間都還不存在時設計權威模型，
等於照著一個不存在的世界去猜它該同步什麼。

## 拍板了什麼

| 題目 | 定案 |
| --- | --- |
| 主模式要不要即時聯機 | **要**。本遊戲不是競技類，防作弊優先度不高 |
| 「最多 2 個 agent」的語意 | 一台主機**同時**運行 2 個。聯機時 remote player 也可以帶 2 個進來 |
| AI 模式裡玩家角色存不存在 | **不存在**。AI 模式不可讀 player 存檔 |
| AI 模式是掛著看還是你不在也跑 | **掛著看**。你下線它就停 |
| 掛 AI 模式養成、回主模式享用 | **是遊戲特色，不是漏洞** |

> [!important] 2 個 agent 是暫定數量
> 日後可能會增加更多，框架要保留彈性 —— 別把「2」寫死進結構裡。

## 存檔分兩層

草案第 6、7 條講的是同一件事：存檔切成兩份，各自獨立。

| | 裝什麼 | 誰讀它 |
| --- | --- | --- |
| **角色存檔** | 所有 player 與 agent | 可以被**多個**世界存檔讀取 |
| **世界存檔** | 地圖資訊 | 一個世界一份 |

這個切法不只是檔案怎麼放。角色跟世界解綁之後，
**「帶自己的 agent 進別人的村莊」是它的直接結果，不是額外要做的功能** ——
remote player 帶 2 個 agent 連進來，就是拿自己的角色存檔去讀別人的世界存檔。
聯機那一階段能省多少事，取決於這兩層在存檔階段有沒有分乾淨。

## 四個階段

### 一、存檔

現在關掉遊戲什麼都不留。

做完之後：養成有意義了，記憶系統也才有地方落腳。

做起來以後才會浮現的真問題：

| 問題 | 說明 |
| --- | --- |
| 併發寫入 | 兩個模式各開一個 process 時，需要單一 session 鎖 |
| 單一時間線 | AI 模式跑掉 3 個遊戲日再切回主模式，狀態怎麼銜接 |

### 二、生活空間

現況是 4 個錨點的測試方塊圖，物品、金錢、商店、工作全是零。
不是可行性問題，是規模問題。

> [!important] 換真村莊要排在物品與商店動工之前
> 否則商店與工作點的座標會重擺兩次。
> 這順帶回答了 [[決策]] 裡「地圖什麼時候換成真村莊」那個待決問題。

### 三、AI 模式

架構已經站在這邊。「唯一區別在 player 不可操作」跟專案核心約束
（Player 能做到的 Agent 也必須能做到）完全同構 ——
Player 只覆寫了「往哪走」這一件事，AI 模式實質上就是把驅動源從鍵盤換成 AI。

要處理的是玩家角色在這個模式不存在，以及**成本**：

- 對話目前沒有輪數硬上限，而且對話輪次豁免速率限制。
  2 隻併發、多人時在場角色又更多，觸發頻率會往上跑。
  「同時 2 隻」這條實際上正在當成本閘門 —— 合理，但別把它當成防護。
- 走 Ollama 時兩隻會在同一張 GPU 上排隊，一起變慢。瓶頸在模型端，不在遊戲端。

### 四、多人

對話層**已經為多人準備好了**：台詞來源設計了「遠端角色等伺服器轉發」這條路，
而且「逐輪生成」這個決定本身就是為多人做的，帳單自動落在正確的人頭上。

沒做的是**世界狀態同步** —— 移動、物品、互動由誰判定。
那是這一階段真正的成本，也是它排最後的原因。

## 這篇改變了什麼

聯機拍板推翻了 [[決策]] 裡三條原本的定案（都已同步過去）：

- 家園單機為主 → **兩模式皆可即時聯機**
- 家園採非同步快照參觀，不做即時共玩 → **可即時共玩**
- 交誼區由專用伺服器當權威 → **主機為權威**

「不做離線託管」那條保留，但理由換了 —— 原本靠快照制成立，現在靠「AI 模式是掛著看」。
