# 計畫

拍板之後的方向與執行順序。全專案的既有決策在 [[決策]]。

## 一句話

```
（進行中：LLM 對話） → 存檔 → 生活空間 → 無 player 的世界 → 多人
```

四個階段接在正在做的 LLM 對話之後。
存檔排第一是因為它同時是共用存檔與記憶系統的前置，做一次解兩件事；
多人排最後是因為在存檔與生活空間都還不存在時設計權威模型，
等於照著一個不存在的世界去猜它該同步什麼。

## 拍板了什麼

| 題目 | 定案 |
| --- | --- |
| 遊戲要不要分模式 | **不分**。差別本來就只在那個世界裡有沒有 player |
| 一個世界要不要有 player | 建立世界時決定**允不允許**加入；允許也**不強制**在場 |
| 世界要不要即時聯機 | **要**。本遊戲不是競技類，防作弊優先度不高 |
| 「單機同時運行 agent 數」的語意 | 一台主機**同時**運行 MVP 5、未來版 10 個（見規格書《00》§3，別寫死）。聯機時 remote player 也照這個數量帶 agent 進來 |
| player 角色會不會由 AI 代打 | **不會**。玩家不在，那個角色就不在場 |
| 世界是掛著看還是你不在也跑 | **掛著看**。你關掉它就停 |
| 在沒有 player 的世界養成、帶回來享用 | **是遊戲特色，不是漏洞** |

## 存檔分兩層

草案第 6、7 條講的是同一件事：存檔切成兩份，各自獨立。

| | 裝什麼 | 誰讀它 |
| --- | --- | --- |
| **角色存檔** | 所有 player 與 agent | 可以被**多個**世界存檔讀取 |
| **世界存檔** | 地圖資訊、允不允許 player 加入 | 一個世界一份 |

這個切法不只是檔案怎麼放。角色跟世界解綁之後，
**「帶自己的 agent 進別人的村莊」是它的直接結果，不是額外要做的功能** ——
remote player 帶自己的 agent 連進來，就是拿自己的角色存檔去讀別人的世界存檔。
聯機那一階段能省多少事，取決於這兩層在存檔階段有沒有分乾淨。

## 四個階段

### 一、存檔

養成有意義了，記憶系統也有地方落腳。

設計見 [[存檔]]，已拆成 issue #19–#23，**全部完成**——併發寫入（兩個 process
開同一份存檔）與角色跨世界（同一份角色存檔被兩個世界同時寫）都靠 #23 的
單一 session 鎖解決，鎖鎖在角色這一層，細節見 [[存檔]]「鎖怎麼做」。

### 二、生活空間

MVP 5 個地點（家／藥草鋪／餐酒館／涼亭／天神之石）已經有真的地圖與錨點（issue #154），
工作站／販賣機機制也接上新座標。兩台販賣機目前共用同一份食物／飲品
`CATALOG`（`bread`／`water`／`wild_fruit`／`ale`），藥草鋪該賣的藥品品項
還沒上架，屬於下一步，見 [[販賣機]]。

> [!note] MVP 範圍已核過
> 這一階段的具體範圍（做哪 5 個地點、工作/社交/戰鬥做到哪、昏迷取代死亡、
> 造型組取代完整外觀系統）見《規格書/13》§三，2026-08-16 逐項核過，
> 不在這裡重複列。

> [!important] 換真村莊要排在物品與商店動工之前
> 否則商店與工作點的座標會重擺兩次。
> 這順帶回答了 [[決策]] 裡「地圖什麼時候換成真村莊」那個待決問題。

### 三、無 player 的世界

架構已經站在這邊。這一階段要做的**不是另一套執行路徑**，
而是讓世界在沒有 player 的情況下照樣成立 —— 這跟專案核心約束
（Player 能做到的 Agent 也必須能做到）完全同構：
Player 只覆寫了「往哪走」這一件事，少一個 player 就只是少一個角色，不缺任何能力。

要做的是世界存檔裡那個「允不允許 player 加入」的旗標，
以及確認沒有人在場時不會有東西在等玩家輸入。剩下的是**成本**：

- 對話目前沒有輪數硬上限，而且對話輪次豁免速率限制。
  2 隻併發、多人時在場角色又更多，觸發頻率會往上跑。
  「同時 2 隻」這條實際上正在當成本閘門 —— 合理，但別把它當成防護。
- 走 Ollama 時兩隻會在同一張 GPU 上排隊，一起變慢。瓶頸在模型端，不在遊戲端。

### 四、多人

對話層**已經為多人準備好了**：台詞來源設計了「遠端角色等伺服器轉發」這條路，
而且「逐輪生成」這個決定本身就是為多人做的，帳單自動落在正確的人頭上。

沒做的是**世界狀態同步** —— 移動、物品、互動由誰判定。
那是這一階段真正的成本，也是它排最後的原因。
