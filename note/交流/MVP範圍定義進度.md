# MVP 範圍定義進度

給下一個 section 接手用。這則記錄「目前定義到哪、還缺什麼」，
不重複已經寫進規格書的內容——每項都指回對應章節，細節去那裡看。
**這則會被刪**：等 MVP 規則定義完、衝突都解完，內容確認已經進規格書後，這則就可以移除。

## 目前狀態

MVP 範圍骨架已核過，見《[[規格書/13_系統分析與系統設計|13]]》§三。

| 主題 | 定案內容 | 對應章節 |
| --- | --- | --- |
| 世界／角色驅動 | 單機跑，角色由 Local／Cloud／Human 三選一驅動；世界旗標 MVP 不開放設定（預設允許），未來版才給房主選 | 13§三、10 |
| 決策來源記錄 | `decision_source`／`model_name` 欄位記錄哪個模型驅動、供角色面板顯示，投放後不可改（同 `personality` 規則）；選雲端時面板不收 API 金鑰，沿用既有 `ai/api.md` 的 `AIConfig` 選 provider；是否公開給其他玩家看延後（P-30） | 05、06、99 P-16／P-30 |
| 地點 | 5 個：家／藥草鋪／餐酒館／涼亭／天神之石；家固定幾間，建角時系統自動分配 | 13§三、07_地點/家 |
| 工作／經濟 | 單一工作站站著賺錢；餐酒館／藥草鋪沿用已實作的販賣機機制；兩間店 MVP **只做販售，不做收購**（貨源地不在 MVP 5 地點內） | 13§三、08 |
| 建角外觀 | 不走 slot 系統，改**固定 6 套造型組**，先用佔位圖 | 99 P-01 |
| 生存 | 死亡改「昏迷」（`health` 歸零觸發，MVP 只走這條路徑，未來版可擴充其他觸發）；可搬運，目的地搬運者自選，可中斷（原地放下）；30 分鐘無人搬自動送藥草鋪，暫定 90 分鐘後解除**所有異常狀態**（統一治療動作，不分拆止血與治療） | 99 P-27、07_地點/藥草鋪 |
| 戰鬥 | `attack` 必中，命中 `health` -15／`injury` +20（暫定）、觸發 `bleeding`（每 tick `health` -1.5 暫定，不設下限保護，扣到 0 觸發昏迷是預期行為）；`medicine` 同時解 `injury` 與止血 | 07、02、08、99 P-28 |
| 移動 | 基礎速度已實作 `SPEED=80.0`；**跑步整個延後到 MVP 之後**（含玩家操作與 AI 自主判斷） | 07、99 P-29 |
| 社交 | `talk`／`give`／`persuade`／`shout` 做；`murmur`（自語）採純機率觸發，跟 `idle` 平行；`perform`／`report` 延後 | 13§三、99 P-23 |
| 對話機制 | `talk` 現況已是多輪對話，非一次性；等待回話逾時暫定 8 秒（AI 對 AI）；三人以上對話評估過偏複雜，MVP 維持 2 人限制 | 技術/talk 動作設計、99 P-22/P-23 |
| 餐酒館要接的既有機制 | 供應酒精類品項會累加 `alcohol`，串上既有的 `drunk` condition（02）與酒精遺失記憶（03§6）——不是新設計，是要記得接上 | 08 |
