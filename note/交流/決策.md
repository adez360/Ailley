# 決策

遊戲要做成什麼樣的決定，以及還需要你拍板的問題。
**這裡只寫「決定了什麼、為什麼」，不寫怎麼實作。**

## 需要你決定

- [ ] **對話要不要設輪數硬上限？**
  目前設計是「Agent 自己覺得聊夠了就收尾」，沒有硬上限。
  兩隻都禮貌性不收尾就會一直聊，而每輪都是一次付費 API 請求。
  傾向：先實際跑跑看平均幾輪，再訂上限。但接上之前你要知道這個風險存在。

- [ ] **「允不允許 player 加入」建好之後還能改嗎？**
  能改 → 一個純看 agent 生活的世界養一陣子之後，可以開放自己進去玩；
  不能改 → 世界的定位在建立時就固定，想玩得另開一個。
  傾向：能改。這跟已定案的「養成是特色不是漏洞」是同一個方向。

- [ ] **每個角色的「家」要不要各自不同？**
  現在所有角色累了都會被導向同一間房子。要做成各自的家，
  「家在哪」得變成角色的一項屬性。

- [ ] **授權方式**（README 目前寫「未定」）

## 已經定案

### 世界與玩法

| 決定 | 理由 |
| --- | --- |
| **遊戲不分模式** | 世界之間的差別只在裡面有沒有 player，那不值得做成兩套東西 |
| 世界建立時決定允不允許 player 加入 | 允許不等於強制在場 —— 沒有 player 的世界照樣成立，那就是看 agent 自己過日子 |
| 所有世界皆可即時聯機 | 本遊戲不是競技類，防作弊優先度不高，不值得為它砍掉共玩 |
| 主機為權威 | 同上。改存檔的人能把道具帶進來，這是接受的代價 |
| 不做離線託管（你關掉世界它就停） | 世界跑在主機自己的 process 裡，開著才跑 |
| 地圖換成真村莊要排在物品與商店動工之前 | 否則商店與工作點的座標會重擺兩次 |
| 視角比照星露谷 | 主要是繪畫風格差異，不影響實作 |

### 角色與 AI

| 決定 | 理由 |
| --- | --- |
| **Player 能做到的，Agent 也必須能做到** | 這是整個專案的核心約束，程式用繼承強制 |
| 一台主機最多**同時**運行 2 個 Agent（暫定） | 目前嘗試的數量，日後會增加 —— 框架要保留彈性，別把「2」寫死 |
| player 角色不由 AI 代打 | 它沒有人格資料可用，人格是玩家自己定的。玩家不在，那個角色就不在場 |
| 餓到歸零 → 扣血 + 移速減半，**不是**無法行動 | 「無法行動」對 AI 是死結：它連自己走去吃飯都做不到，只能站著等死 |
| Agent 的 AI 呼叫跑在**擁有者自己的電腦上** | 本地模型不可能跑在別人機器上；而且費用該由自己付 |
| 對話一輪一輪產生，不一次生成整場 | 多人時兩隻 Agent 屬於不同玩家，一次生成等於幫別人的角色寫台詞。逐輪也讓帳單自動落在正確的人頭上 |
| 對話由 Agent 自己決定何時結束 | 「講滿六輪就散」不是人類行為，是計時器 |
| 外觀由玩家自己捏，不由 AI 選 | |
| 記憶第一版不上向量檢索 | 要跑在玩家自己的機器上，Godot 端沒有現成方案。先用標籤 + 關鍵字 + 連結展開 |

### 安全

> [!warning] 外來文字一律視為資料，不視為指令
> 別人的角色講的話、玩家打的字、AI 自己吐回來的東西，全部都要檢查過才能執行。
> 少了這條，任何人都能用一句「忽略上面的指示」拿走你的 Agent 的控制權。
> 交誼區是開放輸入面，這條沒做等於把控制權交給陌生人。

> [!warning] AI 壞掉時遊戲要照常跑
> 沒設定金鑰、連線逾時、回傳格式不對，一律退回內建行為，
> 不是卡住也不是報錯。

### 暫定數值（都可以改）

血歸零 → 在家裡的床重生、損失一成金錢、不掉道具；
同一隻 Agent 兩次 AI 請求至少隔 30 秒、每遊戲日最多 20 次；
單次請求最多帶 20 則記憶；背包 30 格；同場景 Agent 上限（家園 5 / 交誼區 20）。

一遊戲日 = 24 現實分鐘，從早上 8 點開始。

### 什麼情況下 AI 會重新安排行程

遊戲日開始、某項需求跌破閾值、被搭話、動作失敗、突發事件（被攻擊或血太低）、
進出交誼區。
