# 在地化

目標是把寫死的文字抽出來，讓遊戲能換語系。
技術細節（key 怎麼命名、怎麼加一句話、踩過什麼坑）在 [[在地化]]。

## 現在的狀態

**UI 文字全部抽完，中英文都能跑。** 共 148 條，分兩份表：

- 玩家看得到的 74 條 —— 對話台詞、數值名稱、輸入框提示、AI 狀態訊息、建角面板
- debug 主控台 74 條 —— 指令輸出與 `help` 說明

在遊戲裡打 `locale en` 就整個換成英文，`locale` 看目前語系。

英文是照中文原意翻的，**不是專業譯文**。意思正確、語氣未必到位，
之後找人潤或整批換掉都只要改 `locale/*.csv`，不必碰程式碼。

## 還沒做的

這三件看起來像 i18n 的缺口，其實都是「功能還沒做」，不是翻譯漏掉：

- **玩家角色沒有顯示名。** 玩家角色的名字是 `player`，直接就是識別字，
  英文模式下會看到「Good to see you again, player!」。場景裡固定的兩隻 NPC
  已經有真正的顯示名了（`Agent`＝阿吉、`Agent2`＝阿蘭，見 `npc_schedule.json`
  的 assignments），不會再顯示節點名——但玩家自訂角色命名系統還沒做
- **地點沒有顯示名。** `farm`、`restaurant` 這些現在只當 key 用，
  主控台直接把 key 印出來。要顯示「農場／Farm」得另做一層對照表
- **失敗原因還是代碼。** 搭話失敗時主控台印的是 `TALK_TOO_FAR` 這種代碼。
  目前玩家看不到搭話失敗（只有主控台看得到），所以先沒處理

另外，**遊戲裡沒有切換語系的正式介面** —— 只有 debug 主控台的 `locale` 指令。
等有設定選單時再接上去。

## 加語系的話，字型撐得住哪些

實測 `assets/fonts/Cubic_11.ttf` 的涵蓋範圍（`Font.has_char()` 逐字掃）：

| 字集 | 涵蓋 | 能不能加 |
| --- | --- | --- |
| 平假名 | 82 / 82 | ✅ |
| 片假名 | 82 / 82 | ✅ |
| 日文新字體漢字（測 24 個常見的：図学桜気国体児内円当発変声実対広歳込沢直読写辺点） | 全中 | ✅ |
| 日文標點 `、。` | 2 / 2 | ✅ |
| 西里爾字母 | 64 / 64 | ✅ 俄文也可以 |
| 韓文諺文 | **0 / 11172** | ❌ 要另外找字型或掛 fallback |

**日文可以直接加**，不必換字型也不必掛 fallback。加一個語系就是 CSV 多一欄。

## 需要你決定

- **英文譯文要不要找人潤？** 現在這版意思對，但像
  「Weather's not bad today.」這種台詞語氣是猜的
- **要不要加日文？** 字型這關過了（見上表），剩下的成本純粹是譯文本身
- **角色命名系統什麼時候做？** 這件事卡住「英文模式下 NPC 叫 agent」的問題
