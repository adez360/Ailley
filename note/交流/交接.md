## 下一個 session 必須知道的教訓／限制

> [!warning] 絕對不要自己執行 `gh pr merge`
> 這條是使用者的硬性規則，連使用者自己在對話裡說「照樣合併」都不算數——
> 那句話是「我同意這樣合併」，不是「你去點合併鍵」。準備好、確認可合併狀態
> 就停在那裡，merge 永遠留給使用者自己按。詳見
> `~/.claude/projects/D--Projects-Ailley/memory/feedback_no_self_review_subagent.md`。

> [!important] Rebase 別人的 PR 前，先查 main 是不是已經有人重複實作了同樣功能
> #421 是活教訓：看到衝突不要預設「只是過時，機械式解掉就好」，先用
> `git log -S"關鍵字" origin/main -- <檔案>` 或直接讀 main 對應函式，確認
> main 現有的版本跟這個 PR 想做的事是不是同一件事。

> [!note] 這個 session 沒有 godot-ai MCP 連線，也沒有本機 llama-server／OpenRouter
> 金鑰可用——下個 session 開工前先確認這兩者現在有沒有，會直接決定哪些 issue
> 做得了（#482／#483 需要真的能打 LLM；#514 這種大型 migration 建議有 SQLite
> 連線能驗證再動手；打包 §2.1/§2.4 需要能實跑 `--export-release`）。
