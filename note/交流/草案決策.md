# 草案決策

[[草案]] 那五條的評估結果，以及需要你拍板的問題。
全專案的既有決策在 [[決策]]，這份只處理草案帶進來的新東西。

## 一句話

**四條可以做，一條跟已定案打架。**
第 1 條「主模式也能多人聯機」直接推翻 [[決策]] 裡的「家園不做即時共玩」，
其餘四條與現有架構相容，卡的是工作量與前置，不是可行性。

## 需要你決定

- [x] **主模式到底要不要即時聯機？**
  [[決策]] 已定案「家園採非同步快照參觀，不做即時共玩」，理由是會逼出兩套網路架構，
  而且改存檔的人能把道具灌進共享世界。草案第 1 條 ＋ 第 5 條合起來正好複現這題：
  存檔是本機檔案，聯機時**誰是權威**？
  答「伺服器」則家園不能離線玩；答「本機」則作弊防線沒了。
  先確認你要的是推翻那條定案，還是其實指「交誼區聯機、家園照樣單機」。
  
  答：要可以即時聯機，本遊戲不是競技類遊戲，防作弊優先度不高

- [x] **「最多 2 個 agent」是同時在場，還是總共持有？**
  存檔養 5 隻一次上場 2 隻，跟總共只能有 2 隻，是兩種不同的遊戲。
  
  答：一個主機最多同時運行2個agent，聯機時remote player也可以帶2個agent進來。(2個為目前嘗試的數量，日後可能會增加更多的agent，請保留彈性開發框架)
  
- [x] **AI 模式裡，你的角色存不存在？**
  存在但由 AI 操作 → 它需要人格資料，而人格目前是玩家自己定的；
  不存在 → 共用存檔時它的狀態怎麼推進、切回主模式時人在哪。
  
  答：不存在，`AI模式`不可使用`player`存檔

- [x] **AI 模式是「掛著看」還是「你不在也跑」？**
  掛著看與 [[決策]] 相容（你在線、費用照樣你付）；
  你不在也跑等於**離線託管的變形**，而那條明寫不做。
  字面上讀不出來是哪一種。
  
  答：掛著看

- [x] **掛 AI 模式養好感度、賺錢，回主模式享用 —— 是特色還是漏洞？**
  共用存檔讓 AI 模式自動變成主模式的加速器。
  配上第 1 條的聯機，就直接接上「把道具灌進交誼區」那個顧慮。
  
  答：是遊戲特色不是漏洞
## 逐條評估

| # | 草案 | 判定 |
| --- | --- | --- |
| 1 | 兩模式皆可多人聯機 | **與已定案衝突**，待拍板 |
| 2 | 每台主機最多 2 個 agent | 可行，語意待界定 |
| 3 | 主模式完整生活空間 | 可行，工作量最大 |
| 4 | AI 模式 ＝ 主模式 − 玩家操作 | 可行，架構已經站在這邊 |
| 5 | 兩模式共用存檔 | 可行，但**存檔還不存在** |

### 1 —— 聯機

對話層**已經為多人準備好了**：台詞來源設計了「遠端角色等伺服器轉發」這條路，
而且「逐輪生成」這個決定本身就是為多人做的，帳單自動落在正確的人頭上。

沒做的是**世界狀態同步** —— 移動、物品、互動由誰判定。
那才是當初說的「兩套網路架構」的本體，也是這條真正的成本。

### 2 —— 每台 2 個 agent

當限額不難，真正的約束有兩處，都不是程式問題：

- **成本**：對話目前沒有輪數硬上限，而且對話輪次豁免速率限制。
  2 隻併發、多人時在場角色又更多，觸發頻率會往上跑。
  這條「2 隻」實際上正在當成本閘門 —— 合理，但別把它當成防護。
- **本地模型**：走 Ollama 時兩隻會在同一張 GPU 上排隊，一起變慢。
  瓶頸在模型端，不在遊戲端。

> [!important] 2個`agent`是目前的暫定
> 未來或許會增加更多`agent`

### 3 —— 完整生活空間

現況是 4 個錨點的測試方塊圖，物品、金錢、商店、工作全是零。
不是可行性問題，是規模問題。

> [!important] 這條順帶回答了 [[決策]] 裡的一個待決問題
> 「地圖什麼時候換成真村莊」—— 答案是**在物品與商店動工之前**。
> 否則商店、工作點的座標會重擺兩次。

### 4 —— AI 模式

「唯一區別在 player 不可操作」跟專案核心約束
（Player 能做到的 Agent 也必須能做到）完全同構。
Player 只覆寫了「往哪走」這一件事，AI 模式實質上就是把驅動源從鍵盤換成 AI ——
繼承結構已經替我們準備好了。

界定問題見上方待決兩題。

### 5 —— 共用存檔

共用不是難點，**存檔完全不存在**才是。記憶系統也卡在同一個地方。
做起來之後才會冒出來的真問題：

| 問題    | 說明                                |
| ----- | --------------------------------- |
| 併發寫入  | 兩個模式各開一個 process 時，需要單一 session 鎖 |
| 單一時間線 | AI 模式跑掉 3 個遊戲日再切回主模式，狀態怎麼銜接       |
| 刷取面   | 見上方待決的第五題                         |


## 建議順序

```
存檔 → 生活空間 → AI 模式 → 多人
```

存檔排第一，因為它同時是共用存檔與記憶系統的前置，做一次解兩件事。
多人排最後，因為在存檔與生活空間都還沒有的情況下設計權威模型，
會照著一個還不存在的世界去猜它該同步什麼。
