# 打獵與森林動物

`hunt_small`／`hunt_large`（issue #573）。跟 [[工作站]]／[[販賣機]] 同一種分工：
動作介面在 `character.gd`（`Character.hunt()`），`agent.gd` 只管「怎麼把 LLM
任務變成走過去＋執行一次」。

## 跟 attack／bury 的差異：這兩個動作會擲骰

`hunt_small`／`hunt_large` 在《01-2》`SUCCESS_PARAMS` 表上（`agent.gd` 既有常數，
本次沒改），跟 `gather`／`fish` 同一類「技能檢定」，不是 `attack`／`bury` 那種
硬規則過了就直接放行的必中動作。這決定了 `resolve()` 呼叫時機不能照抄
`_pursue_attack_task()`／`_pursue_bury_task()`（那兩個每個 pursue tick 都呼叫
一次 `resolve()`，因為它們的硬規則分支本來就不擲骰，重複呼叫是安全的）——
`_pursue_hunt_task()` 改成只在真正抵達、即將執行的那一刻呼叫一次 `resolve()`，
照抄 `_pursue_buy_task()` 的呼叫時機，不是 attack／bury 的。理由見
`agent.gd::resolve()` 開頭那段「一次決策一次骰」的既有註解。

## 追逐簡化（07 拍板）

不做「動物邊逃邊被追」的即時互動——`_pursue_hunt_task()` 用跟 `_pursue_attack_task()`
一樣的「走一次、卡住偵測 3 次放棄」節流走到動物旁邊（`Character.HUNT_RANGE`，
32px＝2 格），到了就直接呼叫 `resolve()` 判定一次，成功才呼叫 `Character.hunt()`
寫入狀態。動物本身完全不知道自己正被追——`Animal`（`animal.gd`）只是 Timer
驅動的隨機遊走，不看任何角色的位置。

## 分工

| 物件 | 負責 |
| --- | --- |
| `Animal`（`animal.gd`） | 出沒（Timer 隨機遊走），`game_type` 匯出成 `"small_game"`／`"large_game"`，`remove_from_world()` 被獵殺後收尾 |
| `Character.hunt()` | 距離判定（防呆，見下方）、把 `item_id` 加進獵人背包、移除動物 |
| `Agent._pursue_hunt_task()` | 找最近同類型、且沒有排隊等待刪除的活體 `Animal`、走過去、抵達才呼叫一次 `resolve()`／`hunt()` |
| `Agent.resolve()` 的 `"hunt_small", "hunt_large"` 分支 | 硬規則：附近真的有動物可獵嗎？過了**不** return，落進下面的 `_roll_success()` 真的擲骰 |

## `Character.hunt()` 不是機率判定

跟 `bury()`／`attack()` 一樣「一路檢查，任何一關不過就回失敗碼」，但這裡的
檢查全部是防呆（動物在擲骰之後、真正執行之前的空窗期跑走／被別人先獵走），
不是本身的成功率。`Character.hunt()` 本身不呼叫 `resolve()`、也不知道成功率
這回事——那個機率是呼叫端的責任：`Agent._pursue_hunt_task()` 只有在
`resolve()` 骰到「成功」之後才會呼叫 `hunt()`。直接呼叫 `Character.hunt()`
（例如下方驗證段落的情境一）會略過整個擲骰，任何呼叫端要不要擲骰是自己的
選擇，不是 `hunt()` 保證的。

`animal.remove_from_world()` 呼叫的是 `queue_free()`，節點要到那一幀結束才真的
從樹上消失——這段空窗期裡 `is_instance_valid()` 仍回 true。若同一 tick 內兩個
角色都鎖定同一隻動物，兩邊都會通過原本的檢查、各自入袋一次戰利品。`hunt()`
與 `_find_nearest_animal()` 因此都額外檢查 `animal.is_queued_for_deletion()`：
已經在排隊等刪除的動物視同不存在，第二個獵人拿到 `HUNT_TARGET_NOT_FOUND`，
不會重複入袋。

## 森林資源庫存（`regen`）不在這則範圍內

《07 地點與行動》§1-1 的地點資料結構定義了 `resources`／`regen` 欄位（森林
`regen: {"small_game": 36, "large_game": 144}`），但這是**地點層級的抽象庫存**，
跟「場上有幾隻 `Animal` 節點」是兩件事，目前完全沒有程式碼消費 `regen` 這個值。
本則 issue 只做「獵到場上實際存在的 `Animal` 節點」，不做「森林資源池扣減與
按 `regen` 這個 tick 數重新補上」——動物被獵殺後單純 `queue_free()`，數量會不會
補回、要不要另外生成新的 `Animal` 實例，留給之後需要「資源可能枯竭」這個玩法
時再決定，見《99 待規劃項目清單》。

## 場景配置

`loc_forest` 錨點（`PlaceAnchors/forest`）與三隻 `Animal` 實例
（`Level/Animals` 底下，`scenes/animal.tscn`）已擺進 `level.tscn`，
座標落在地圖右上角一塊確認過 `NavGrid` 可走的空地（`small_game` x2、
`large_game` x1）。`Animal` 場景本體：`CharacterBody2D` 根節點、
`CircleShape2D` 半徑 6（比照 Player）、`collision_layer=2`／`collision_mask=1`
（比照 Character，只撞地形不撞其他角色）、子節點 `WanderTimer`（`animal.gd`
靠 `$WanderTimer` 讀取，改名會炸）、`Polygon2D` 三角形佔位視覺。

已用 `project_run` + `game_eval` 對主 checkout（`feat/forest-hunting`）驗證四種情境：

1. 直接呼叫 `Character.hunt()`：Player 傳送到 `SmallGame1` 旁，`hunt()` 回傳
   `""`（`HUNT_OK`），兩幀後 `is_instance_valid(animal) == false`，背包
   `slots[0] == {"item_id": "small_game", "count": 1, ...}`。
2. `Agent._pursue_hunt_task()` 完整管線：Agent2 傳送到 `LargeGame1` 旁，設定
   `_current_task = {"action": "hunt_large", "source": "llm", ...}`，第一次呼叫
   即擲骰成功、動物被移除、`last_action_result == ""`。
3. 附近沒有同類型動物時 `resolve()` 正確擋下：三隻動物獵完後，
   `agent.resolve("hunt_small", {})` 與 `agent.resolve("hunt_large", {})`
   皆回傳 `{"success": false, "reason": "附近沒有可以獵的動物"}`。
4. 重複掉落防呆（CodeRabbit review, PR #621）：Player 與 Agent 同時鎖定
   `SmallGame2`、同一 frame 內先後呼叫 `hunt()`，第一個回傳 `""`，第二個回傳
   `"TARGET_NOT_FOUND"`——`is_queued_for_deletion()` 檔下了同幀重複入袋。

`logs_read(source="game")` 只看到 `Character player 獵到了一隻 small_game`
與例行的 `CharacterStatePersistence` 存檔紀錄；`logs_read(source="editor")`
的警告全是既有檔案的 GDScript reload 雜訊（shadowing、integer division 等），
不在這次改動涉及的行數上，跟本次修改無關。
