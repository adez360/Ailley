# 視覺感測

角色能不能看到別人。掛在角色底下的元件，回報「現在看得到哪些角色」，含視線遮蔽判定。

## 檔案

| 檔案 | 角色 |
| --- | --- |
| `scripts/character/vision.gd` | `class_name Vision extends Area2D`，掛在角色底下的元件 |
| `scripts/character/character.gd` | 基底加 `@onready var vision`，與 `stats` / `relationships` 同一種 `get_node_or_null` 慣例 |
| `scripts/character/agent.gd` | 接 `spotted` 訊號，決定要不要有反應 |
| `scripts/ui/debug_overlay.gd` | `vision` 疊圖圖層 |

## 核心決策

> [!important] Vision 只回報「看到誰」，不決定看到之後做什麼
> 反應行為（停下來、說「！」）放在 `agent.gd`，不放在元件裡。
>
> 理由不是美觀，是為了接 LLM：**看得到誰**是 payload 裡的 `context.visible`，
> **要不要理他**是模型的輸出。現在就把這條線畫好，
> 接 AI 時不必再把感知從行為裡拆出來。
>
> 這也讓 Player 自然地「有視野但不自動反應」—— 它同樣掛 Vision，
> 只是沒有接 `spotted`。符合專案那條「Player 能做到的 Agent 也必須能做到」的反面：
> Agent 有的感知 Player 也有，差別只在誰來決定行為。

> [!important] 訊號只在可見集合變動時發，不是每幀
> 內部維護一份「目前看得到誰」，成員進出時才 emit `spotted` / `lost`。
>
> 若改成每幀逐目標判定並直接觸發反應，會變成「只要看得到就一直觸發」——
> 反應該發生在**進入視野的那一刻**，不是持續發生。
> 這種寫法的症狀很隱蔽：看起來會動，因為 2 秒的暫停計時器一直被重設。

> [!important] 視線查詢用 `intersect_ray`，不掛 RayCast2D 節點
> 直接查 `direct_space_state`：不必為了一次性查詢養一個節點，
> 也不必每幀查（`CHECK_INTERVAL = 0.2` 秒）。
>
> 牆不會動、角色一秒走 80px，0.2 秒的延遲在「轉角遇到人」的體感上看不出來。

> [!warning] Area2D 會偵測到自己的父 CharacterBody2D
> 少了 `if other == _character: return` 這行，每個角色都會回報「我看到我自己」。
> 這不會報錯，只會讓之後餵給 LLM 的 `context.visible` 永遠多一筆自己。

> [!warning] CircleShape2D 是 instance 之間共用的 sub-resource
> 兩隻 Agent 是同一份 `agent.tscn` 的 instance，不在 `_ready()` 裡 `duplicate()`
> 的話，調整其中一隻的 `radius_tiles` 會連帶改到另一隻。

## 碰撞設定放在場景，不放程式

沿用 [[Character 基底與 Agent]] 那條「設定在 .tscn，不寫在腳本」的規則，
免得 inspector 改了卻被程式蓋掉：

| | collision_layer | collision_mask |
| --- | --- | --- |
| Vision（Area2D） | 0（不該被任何人偵測到） | 2 `character` |
| 視線射線 | — | 1 `terrain`（人不是牆，不會擋視線） |

Vision 節點的 `position` 設為 `(0, 6)`，對齊角色 `CollisionShape2D` 的偏移 ——
半徑判定與視線判定要用同一個原點，否則貼牆時兩者會不一致。

## 除錯

主控台 `debug vision`。畫兩樣東西：

- 每個角色的視野圈
- 從角色連到**真的看得到的人**的直線

只畫圈看不出視線判定有沒有生效 —— 隔著牆時圈仍然涵蓋對方，但線不會出現。

> [!important] 除錯繪製不寫在 `vision.gd` 裡
> 疊圖走 [[尋徑與 Debug 主控台]] 既有的 `debug <項目>` 指令。
> 遊戲實體不該讀輸入，也不該為了除錯而帶 `_draw()`。

> [!important] 「陌生」的判定來自 `Relationships.has_met()`
> 而 `has_met()` 只認 `note_meeting()`（好好講完一場話），不認「被查過好感度」。
> 這條在 [[talk 動作設計]] 有完整說明 —— 曾經因為查詢會建立紀錄，
> 搭話後立刻走開就足以讓 Agent 從此把對方當熟人，初見反應再也不會發生。

> [!note] 「愣完重算行程」讓一個既有的抵達判定 bug 變成必現
> 距離判定的門檻是 2px，而尋徑以 16px 的格為單位，中間那段是死角。
> 加 Vision 之前只在對話結束時偶爾踩到，加了之後每次愣完都會踩。
> 判定規則見 [[Character 基底與 Agent]]。

## 驗證

`main.tscn` 實跑（Godot 4.5.1-stable），用 `game_eval`：

- 三個角色互相看得到對方兩個，且**都不包含自己**
- 隔一道牆時相距 32px（半徑 80px）但雙方 `get_visible_characters()` 皆為空
- `_noticed` 每個對象只記一次，走出視野再走回來不會重複驚訝
- `debug vision` 疊圖畫得出圈與視線連線（截圖確認）
- 乾淨執行 43 秒，game log 無警告
