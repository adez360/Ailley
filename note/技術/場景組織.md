# 場景組織

`scenes/` 底下兩個常態場景長期並存，職責固定分開：

| 場景 | 裝什麼 |
| --- | --- |
| `main.tscn` | 只放已拍板定案的內容——功能一旦定案就留在這裡，不會再搬走 |
| `sandbox.tscn` | 新功能先在這裡做，還沒拍板前不進 `main.tscn` |

`sandbox.tscn` 目前只有一個空的 `Node` 根節點（`Sandbox`），要新增內容一律走 godot-ai MCP（`node_create`／`script_attach` 等），不要手改 `.tscn`——跟本專案所有場景操作同一條規則，見 `Ailley/CLAUDE.md`。

## `main.tscn` 現況（2026-08-24 盤點）

盤點過當時 11 個頂層節點（`Level`／`PersistentUI`／`Player`／`Agent`~`Agent5`／`Workstation`／`VendingMachine`／`VendingMachineHerbShop`），逐一對過 `note/技術/` 底下對應的系統筆記，全部標記 `已實作`——沒有找到需要搬去 `sandbox.tscn` 的實驗性/未拍板節點。`talk` 動作設計（涵蓋 `PersuadeDialog`／`ChatInput`）雖然狀態是 `進行中`，但屬於核心互動機制的持續打磨，不是可以獨立隔離的實驗性功能，不搬。

之後每次要在 `main.tscn` 新增節點前，先確認對應功能是否已拍板；還沒拍板的一律先進 `sandbox.tscn`，定案後再搬過去，不要讓兩者的分工再次混在一起。
