# 主選單

`run/main_scene` 指向 `scenes/main_menu.tscn`，取代原本開機直接進 `main.tscn`
（遊戲世界）的流程。入口：**繼續遊戲**（有存檔才顯示，issue #343）、
**開始遊戲**、**銘謝**（issue #295）、**離開遊戲**（issue #811）。

具體文案、按鈕位置、排版留給前端組決定，這裡只定義結構與行為。

## 場景結構

```
MainMenu（Control，main_menu.gd）
  Background（ColorRect，全螢幕）
  TitleLabel（遊戲名稱 "Ailley"，寫死不走翻譯——專有名詞）
  ButtonsBox（VBoxContainer，置中）
    ContinueButton（預設隱藏，SaveService.has_world(GameManager.DEFAULT_WORLD_ID)
                    為 true 且 SaveService.is_world_data_valid(...) 通過才顯示）
    StartButton / CreditsButton / QuitButton
    LoadErrorLabel（預設隱藏，存檔存在但讀不出來或格式不完整時才顯示 UI_MENU_LOAD_ERROR）
  Scrim（ColorRect，全螢幕半透明，預設隱藏）
    CreditsPanel（Setting menu.png 九宮格，樣式沿用 [[UI 版面與素材規格]] 的
                  StatusPanel 做法：region_rect (11,12,106,122)、
                  texture_margin_top=28）
      TitleBg / TitleLabel
      VBox
        QwenLabel / LlamaCppLabel（《16 打包與發布規格書》§2.2 列名的
                                    兩項第三方授權：Qwen2.5 Apache-2.0、
                                    llama.cpp MIT）
        HintLabel
```

## 行為

- **繼續遊戲**：只設定 `GameManager.continue_requested = true` 再
  `change_scene_to_file`——實際套用存檔在 `main.tscn` 根節點的
  `scripts/core/main_scene.gd`，理由與細節見 [[存檔]]「開場讀檔」
- **開始遊戲**：`GameManager.continue_requested = false`，接著呼叫
  `GameClock.reset_to_new_game_start()`（#606）與
  `GameManager.reset_for_new_game()`（#875）再
  `get_tree().change_scene_to_file("res://scenes/main.tscn")`——前者把
  `day`/`hour`/`minute` 拉回 `1`/`8`/`0`，後者把只有讀檔
  （`apply_world_save_data()`）才會寫入的 `character_library`／
  `embodied_character_id`／`allow_player_join`／`identity_assignments`
  清回全新狀態（見 [[存檔]]「角色庫已接進世界存檔」）。`GameManager`／
  `GameClock` 都是全域 autoload，整個 process 存活期間不會自動重新初始化，
  同一次執行裡玩過一次「繼續遊戲」，這些欄位會一路殘留到之後任何一次
  「開始新遊戲」，不補這兩個重置就會帶著上一輪讀檔的殘留狀態進新遊戲。
  不動磁碟上的存檔檔案——舊存檔還在，之後仍可被「繼續遊戲」讀到。
  `_ready()` 對 `StartButton` 呼叫 `grab_focus()`，開場就有預設焦點，
  純鍵盤也能直接 Enter 開始
- **離開遊戲**：`QuitButton` 呼叫 `get_tree().quit()` 直接關閉遊戲行程
  （issue #811）。主選單階段還沒有進行中的遊戲、沒有角色/世界狀態要存，
  不走 `esc_menu.gd::_on_exit_pressed()` 那套先存檔的流程——兩者情境不同，
  這裡不需要 `GameManager.save_before_leaving()`
- **銘謝**：顯示 `Scrim`（連帶蓋住的 `CreditsPanel`）。`CreditsPanel` 本身沒有
  可聚焦的控制項，開啟時把 `ContinueButton`／`StartButton`／`CreditsButton`／
  `QuitButton` 的 `focus_mode` 暫時設成 `FOCUS_NONE`，避免面板開著時 Tab／Enter
  還能繞過去直接開始/繼續/離開遊戲；關閉時復原並把焦點交回 `CreditsButton`
- **關閉銘謝**：點面板外或按 `ui_cancel`。目前專案沒有另外幫 `ui_cancel` 綁
  搖桿鍵位，Godot 內建預設只含 Esc 鍵，跟其他面板（狀態表、天神之石、
  販賣機選單、暫停）同一套慣例，差別只在於「用 action 而不是寫死 keycode」，
  不代表現在就有搖桿支援。
  點面板外的判定不用自訂 hit-test——`Scrim` 蓋滿全螢幕且 `mouse_filter`
  是預設值 `STOP`；`CreditsPanel` 本體同樣預設 `STOP`。它底下的 `TitleLabel`
  跟 `VBox` 裡的 Label 群沒有覆寫，走 Label 預設值 `IGNORE`，點擊穿過；`VBox`
  本身（`VBoxContainer`）沒有覆寫則走 Container 預設值 `PASS`——PASS 一樣會
  把事件繼續往上送，最終落到 `CreditsPanel` 本體才真正被吃掉。`Scrim` 收到
  `gui_input` 就代表點在面板外，只認滑鼠左鍵（`button_index == MOUSE_BUTTON_LEFT`），
  滾輪 tick／右鍵／中鍵不會誤觸關閉；靠 Control 內建的事件冒泡順序解決，
  不用像 `status_panel.gd` 那樣自己算世界座標

## 翻譯 key

新增於 `locale/game.csv`：`UI_MENU_CONTINUE`、`UI_MENU_LOAD_ERROR`、
`UI_MENU_QUIT`（issue #811，「離開遊戲」——刻意不沿用 Esc 選單的
`UI_MENU_EXIT`，那個字串講的是「回主選單」，跟這裡「直接關閉遊戲」語意
不同，共用同一個 key 會讓兩個情境的文案綁死）。
`UI_MENU_START`／`UI_MENU_CREDITS`／`UI_CREDITS_QWEN`／`UI_CREDITS_LLAMACPP`
是既有 key。關閉提示重用既有的 `UI_STATUS_CLOSE_HINT`，不重複造一個一樣的字串。

> [!warning] 改 `locale/*.csv` 後要重 import 才會反映到執行期
> `filesystem_manage(op="reimport")` 對單一 csv 路徑呼叫一次不保證夠——
> 實測跑過一次 `project_run` 後新 key 還是查不到翻譯結果（`TranslationServer.translate()`
> 原樣吐回 key），要先 `filesystem_manage(op="scan")` 做一次完整掃描、
> 再 `reimport` 該 csv，重開一次 `project_run` 才生效。改完務必用
> `game_eval` 呼叫 `TranslationServer.translate("你的新 key")` 實際驗證過
> 不等於原樣吐回，不要只看畫面像不像中文就當作過了。
