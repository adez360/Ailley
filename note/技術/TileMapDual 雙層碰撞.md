# TileMapDual 雙層碰撞

> [!warning] 症狀：debug 的 solid 疊圖上很多空地被判成障礙
> 不是疊圖畫錯 —— 玩家與 Agent 真的走不進去，A\* 也繞路。

## 根因

TileMapDual 會產生**兩個**都有碰撞的 TileMapLayer：

| 層 | 位置 | 說明 |
| --- | --- | --- |
| `TileMapDual`（世界層） | (0, 0) | 你畫的那層。外掛用 ghost shader 讓它隱形，**但沒關碰撞** |
| 生成的 DisplayLayer | **(-8, -8)** | 轉場圖，偏移半格 |

兩層共用同一個 TileSet。世界層只用兩塊標記圖磚：

```
(0,3) x 383   空地標記，碰撞多邊形 0
(2,1) x 177   牆標記，  碰撞多邊形 1   ← 雙層碰撞的來源
```

顯示層則用滿全部 16 塊。那塊 `(2,1)` 同時是**資料標記**和**實體牆**，
碰撞一掛上去兩層都生效，牆就比看起來胖半格。

## 外掛原本的設計是把碰撞放在顯示層

三個證據：

1. `tile_map_dual.gd:99-102` 註解寫「世界層的圖磚不需要被看見，只有 DisplayLayer 該可見」
2. `display_layer.gd:48` 明確把 `collision_enabled` 傳給顯示層
3. 世界層的「空地」標記 `(0,3)` 碰撞多邊形是 0 —— 正是「世界層不該有碰撞」的慣例

> [!important] 但照原設計做，對這個專案反而更糟
> 顯示層在偏移半格的網格上。碰撞放那裡，NavGrid 的格中心就落在圖磚**角落**，
> 半徑 6 的探測圓同時碰到周圍 4 塊。
>
> | 碰撞放哪 | 對齊 | 偽障礙 |
> | --- | --- | --- |
> | 顯示層（外掛原設計） | 偏移半格 | **25 格** |
> | 世界層（現在） | 與 NavGrid 完全對齊 | **0 格** |
>
> 外掛是為一般 2D 平台／俯視遊戲設計的，那種遊戲只在乎碰撞體貼合美術。
> 這個專案是**格子制 A\\* 尋徑**，格線對齊比貼合美術重要。

## 修法：直接改外掛

`addons/TileMapDual/display_layer.gd:48`，把 `collision_enabled` 改成不複製、恆為 false，
並在原地寫清楚理由與前提。

曾經先做過「場景掛勾」的版本（一個節點在開場一秒內持續把顯示層碰撞關掉），已廢棄。
改外掛好在哪：

| | 改外掛 | 掛勾（已廢棄） |
| --- | --- | --- |
| 程式碼量 | 1 行 | 77 行 + 場景節點 |
| 節點順序 | 無所謂 | 要排在 TileMapDual 之後、NavGrid 之前 |
| 開場輪詢 | 不用 | 1 秒內每幀重套（外掛 deferred 更新會蓋回去） |
| NavGrid 第一次掃就正確 | 是 | 否，先掃到 208 再重掃 177 |
| `grid_built` 時序 bug | 不存在 | 存在 |

最後一列是決定性的。掛勾版本裡 NavGrid 會在碰撞修正生效**前**就發出 `grid_built`，
Agent 收到訊號拿著胖網格出發，開場就報 `走不到 home_001` 而且不會重試。
改外掛之後顯示層從頭到尾沒有碰撞，這個問題自然消失。

> [!important] 前提：碰撞必須來自世界層的標記圖磚
> 哪天改成只在轉場圖上畫碰撞、世界層標記不畫，就會變成**完全沒有碰撞**。
> 這個前提已寫在改動處的註解裡。

> [!note] 外掛更新會蓋掉這個修改
> 但 `addons/` 有進版控（`git ls-files` 查得到 `display_layer.gd`），
> 更新時 git 會顯示衝突讓你發現。
> `tile_map_dual_legacy.gd:131` 有同樣一行，這個專案沒用到 legacy 節點所以沒動。

## 驗證

掃過整個已繪製範圍，比對「畫的是不是牆」與「NavGrid 判不判為障礙」：

| | 修復前 | 修復後 |
| --- | --- | --- |
| 牆且有擋 | 107 | **177** |
| 牆卻沒擋（會穿牆） | 0 | **0** |
| 非牆卻被擋（偽障礙） | 25 | **0** |

開場日誌從 `solid=0 → 208 → 177`（三次掃描含修正）變成 `solid=0 → 177`（一次到位），
且不再有任何 `走不到` 警告。顯示層照樣畫了 609 格，渲染完全不受影響。
