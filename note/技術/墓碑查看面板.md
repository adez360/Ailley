# 墓碑查看面板

點擊已安葬角色，唯讀顯示「這個人是誰」（issue #385）：個性、生平、臨終遺言。
不含悼詞（其他角色/玩家留言）——這條需求已撤，見下方「範圍界線」。

## 觸發與面板

`EpitaphInput`（`hud.tscn`）是獨立的 `CanvasLayer`（`Panel >
TitleBg/TitleLabel/StatusLabel/ContentScroll/ContentVBox`）。開關機制跟
`status_panel.gd` 同一套：`_input()` 而非 `_unhandled_input()`，共用
`selection.character_at()` 找點到誰——但只對 `is_buried == true` 的角色開
面板，未安葬的屍體沒有墓碑（跟《規格書09》§4-3「未安葬不顯示遺言/生平」
同一種語意）。

跟 `status_panel.gd` 一樣不吃掉點擊事件，只在 Esc 關閉那個分支才
`set_input_as_handled()`——空地點擊要繼續傳給 `selection.gd` 取消選取。
這代表點擊已安葬角色時 `StatusPanel` 也會一起開（既有現象，兩邊互相獨立，
不是這裡造成的耦合）。

## 顯示內容

點開後 `_refresh_content()` 動態產生內容（`ContentVBox` 底下的
`Label` 陣列，跟 `status_panel.gd` 的 `StatsBox`/`plan_list` 同一種
「唯讀資料唯讀顯示」寫法，不是預先擺好的固定節點），依 `is_anonymous`
分兩種：

**具名（`is_anonymous == false`）**：標題顯示角色名字，三段內容：

- **個性**：`Character.personality` 現有的 10 項引擎數值（`Personality.
  PERSONALITY_KEYS`），逐項標籤來自新增的 `Personality.PERSONALITY_LABELS`
  對照表（跟 `Stats.SPEC` 的 `"label"` 同一種做法）。**顯示的是死掉當下
  的即時值，含睡前反思 `apply_personality_delta()` 累積的漂移**——決策
  迴圈死後停止，這個欄位死後不會再變，不需要另外拍照存一份
- **生平**：`Agent.life_highlights`（#381，引擎彙整，絕不讓 LLM 潤飾）。
  只有 `Agent` 有這個欄位，`Player` 死亡（若發生）顯示佔位文案
  （`UI_GRAVE_NO_LIFE_HIGHLIGHTS`）
- **臨終遺言**：`Character.last_words`，死者自己的 LLM 產生，可能是
  `null`（來不及開口）——顯示專屬文案（`UI_GRAVE_NO_LAST_WORDS`），跟
  「這項沒有資料」的泛用佔位符（`EMPTY_PLACEHOLDER`「—」）分開，因為
  「沒能留遺言」本身是死亡的一種狀態，不是單純缺資料

**無名碑（`is_anonymous == true`，《規格書09》§3-4／§4-3）**：
`corpse_decay` 達 100 沒人安葬時 `_erect_unmarked_grave()`（#387）自動
立碑設下的欄位。標題不顯示真名（`UI_GRAVE_ANONYMOUS_TITLE`），個性/生平/
遺言整段不顯示，只留「無人知曉他是誰」（`UI_GRAVE_ANONYMOUS_UNKNOWN`）跟
死亡日期（`UI_GRAVE_ANONYMOUS_DAY`，讀 `death_day`）——見
`_add_anonymous_lines()`。面板本身照樣會開，不是無名碑就不能點。

## 範圍界線：悼詞（他人留言）已撤，不在這個面板裡

原始 issue #385（「eulogy UI for gravestones」）字面上要做的是「其他角色/
玩家對墓碑留悼詞」，也确實有配套的 SQLite 表（`grave`／`grave_epitaphs`，
issue #382）與字數拍板（issue #368）。2026-08-28 拍板：**不做悼詞**，這則
issue 改成本文件描述的唯讀查看面板。

- `grave`／`grave_epitaphs` 兩張表本身**不受影響**——它們是 #382 就已經
  合進 main 的既有 schema，不是這則改動新增的，繼續留著（沒有任何呼叫端
  寫入，跟改動前一樣）
- 原本這裡的 `GraveEpitaphPersistence.gd`（悼詞讀寫）與面板上的悼詞輸入框
  已整段移除
- NPC/AI 角色透過 LLM 動作留悼詞——這件事本來就不在範圍內（`epitaph` 從
  沒進過 `IMPLEMENTED_ACTIONS`），現在整個悼詞功能都不做，這點延續不變

## 驗證

用 godot-ai `game_eval` 端到端跑過（`project_run` → 切到 `main.tscn` →
直接呼叫 `_open()`，因為模擬滑鼠點擊事件在 `_input()` 收不到——跟
`status_panel.gd` 既有點擊機制同一種測試環境限制，不是這次改動的問題；
點擊觸發機制本身沿用未改動的既有程式碼）：

- 已安葬角色 `_open()` → 面板正確開啟，`title_label` 顯示角色名字，
  三段內容都正確渲染（個性 10 行含漂移後數值、生平列表加「・」項目符號、
  遺言原文）
- `personality["grudge"]` 手動改成 12 後重開面板 → 顯示的是 12，不是
  建角當下的原始值，確認讀的是即時漂移值
- `last_words = null` 且 `life_highlights` 清空 → 兩段正確顯示各自的
  佔位文案，不是空白也不是報錯
- `panel.panel.visible`／`content_vbox.get_child_count()` 直接查驗確認
  面板狀態與內容筆數符合預期
- `is_anonymous = true`、`death_day = 42` → 標題顯示「無名墓碑」，內容只有
  「無人知曉他是誰。」跟「死於第 42 天」兩行，個性/生平/遺言三段都沒有
  渲染（CodeRabbit review 抓到：先前完全沒讀 `is_anonymous`，無名碑一樣
  顯示全部內容，違反《規格書09》§4-3）
- 對沒有 `life_highlights` 欄位的 `Player`（`_corpse as Agent` 轉型失敗）
  直接 `_open()` → 修正前會在 `_add_life_highlights_lines()` 拋執行期錯誤
  「Trying to assign an array of type Array to a variable of type
  Array[String]」（三元運算子兩側型別不相容，`[]` 字面值不會自動轉型），
  改成 `if`/`else` 明確賦值後正常顯示 `UI_GRAVE_NO_LIFE_HIGHLIGHTS` 佔位文案
