# 昏迷狀態機制

**規格版本**：《99》P-27、《99》P-28（攻擊傷害與流血）
**MVP 簡化**：見《13》§三
**死亡流程**：見《09》§1，昏迷逾時未獲救治轉死亡的實作見下方「Phase 2 現況」

## 核心設計

昏迷（`incapacitated`）是健康度歸零時觸發的新狀態，是死亡的前置狀態——`health ≤ 0`
一律先觸發昏迷，逾時未獲救治才轉入死亡流程，不會直接死亡。

| 項目 | 規格 |
| --- | --- |
| **觸發** | `health ≤ 0`（通常由 `attack` 打到） |
| **表現** | 石化原地（比照 `petrified`，但非終局狀態） |
| **結束方式** | 1. 被搬走（#161 haul 動作）2. 或 30 分鐘內無人搬運→轉入死亡流程（#379） |
| **搬運速度** | 搬運者速度 50%；每 tick 額外 -3 體力 |
| **治療時間** | 60 遊戲分鐘後解除所有異常狀態、`injury` 歸零、`health` 恢復（目前沒有呼叫端會觸發，見下方「Phase 2 現況」） |

## 實裝現況

- **昏迷狀態定義**（`CONDITION_INCAPACITATED`）
- **觸發與計時**
  - `_start_incapacitation()`：health ≤ 0 時紀錄昏迷開始時間
  - `_update_incapacitation()`：每遊戲分鐘檢查是否達 30 分鐘或被搬走
- **治療邏輯**
  - `_send_to_herb_shop_for_treatment()`：`global_position` 直接瞬移到
    `places.gd`（`place_anchors` 群組）解析出的 `herb_shop` 錨點座標，
    不做「NPC 走過來救」的移動演出（#272，《99》P-27 明講的 MVP 簡化）。
    瞬移那一刻不用額外 `stop_moving()`——`_is_movement_locked()` 已經在
    `CONDITION_INCAPACITATED` 期間鎖死移動，不會有殘留路徑跟瞬移搶位置
  - `_update_treatment()`：每遊戲分鐘檢查是否達 60 分鐘
  - `_complete_treatment()`：恢復 health/injury、清除所有異常狀態；因為
    整段治療期間 `_is_movement_locked()`（見下方）鎖住移動，角色從瞬移進來
    到治療完成全程沒離開藥草鋪，「在藥草鋪蘇醒」不需要額外收尾邏輯
- **移動鎖定**：`_is_movement_locked()` 同時查 `CONDITION_INCAPACITATED` 與
  `_treatment_start_minute != -1`——昏迷期間鎖，瞬移進藥草鋪後昏迷 condition
  已解除但治療計時器接手鎖住，直到 `_complete_treatment()` 才真正解鎖
- **掛點 for #161**
  - `set_being_carried(bool)`：haul 動作呼叫，標記「正在被搬運」
  - 昏迷計時器自動結束

## 相關程式碼

### Character.gd 昏迷相關方法

```gdscript
# 狀態變數
var _incapacitation_start_minute := -1
var _is_being_carried := false
var _treatment_start_minute := -1
var _treatment_location := ""

# 核心邏輯
func _start_incapacitation() -> void
func _update_incapacitation() -> void
func _end_incapacitation() -> void
func _send_to_herb_shop_for_treatment() -> void
func _update_treatment() -> void
func _complete_treatment() -> void

# 掛點
func set_being_carried(is_carried: bool) -> void
```

### 存檔與還原

`get_save_data()` 儲存 `incapacitation_start_minute`、`is_being_carried`、`treatment_start_minute`、
`treatment_location`；`load_save_data()` 還原這四項，並在昏迷中但尚未送醫
（`incapacitation_start_minute != -1` 且 `treatment_start_minute == -1`）時重建
`CONDITION_INCAPACITATED`——治療狀態優先，治療中的存檔不重建這個 condition。
`-1` 表示尚未進入昏迷／治療，空字串表示沒有治療地點。

死亡欄位（`is_dead`／`death_tick`／`death_day`／`death_at`／`death_cause`／
`death_location_id`／`last_words`／`corpse_decay`／`is_buried`／`grave_id`）
一併存讀，規則見下方「Phase 2 現況」：`is_dead` 缺席一律預設 `false`（舊存檔
沒有死亡機制，缺欄位＝未死亡，不是沿用目前值）；`is_dead == true` 時其餘死亡
欄位照存檔值還原，`treatment_start_minute`／`treatment_location` 一併清空；
`is_dead == false` 時反過來清掉所有死亡欄位與 petrified 外觀殘留，確保連續
載入不同存檔時死亡狀態不會黏著。

## 踩坑與注意

### 時間計算

- 使用 `GameClock.hour * 60 + GameClock.minute` 計算遊戲分鐘
- 跨日時需用 `% (24 * 60)` 處理（目前未實裝跨日檢查，但保留空間）
- 每遊戲分鐘檢查一次（透過 `GameClock.time_changed` 信號驅動）

### 狀態不是「門檻自動」

- 生理衍生類 condition（injured、bleeding 等）是「門檻自動」：條件消失下次檢查就移除
- 昏迷**不是**：一旦進入必須明確結束（被搬走、完成治療，或轉入死亡流程）
- 即使 health 變正，也不會自動清除昏迷狀態

### 搬運觸發昏迷結束

`haul` 動作開始搬運時呼叫 `set_being_carried(true)`，`_update_incapacitation()`
下次檢查就會經 `_end_incapacitation()` 結束昏迷；停止搬運呼叫
`set_being_carried(false)`。

## Phase 2 現況（issue #379）

昏迷 30 分鐘無人搬走時，`_update_incapacitation()` 呼叫 `_die()` 轉入
《09》§1 的死亡流程，取代原本「自動傳送藥草鋪治療」這個結局
分支。`_send_to_herb_shop_for_treatment()` 保留在 Ailley/scripts/character/character.gd
裡，但目前沒有呼叫端——留給「天神主動介入送醫」那個 issue 接上（見下方待做）。

死亡流程本身：`is_dead`／`death_tick`／`death_day`／`death_at`／`death_cause`／
`death_location_id`／`corpse_decay` 這幾個欄位由 `_die()`
（Ailley/scripts/character/character.gd）統一寫入並清空 conditions 只留
`petrified`；`last_words` 由 Agent 覆寫的 `_request_last_words()` 非同步問 LLM
（`Ailley/scripts/ai/prompt_builder.gd::build_last_words_envelope`／
`Ailley/scripts/ai/ai_schema.gd::validate_last_words`），Player 沒有 LLM 決策維持
`null`。
`corpse_decay` 每 tick（10 遊戲分鐘）+0.7，限制在 `[0, 100]`（死亡當下那個 tick
跳過，第一次累加從下一個 tick 開始），達到 100 之後怎麼處理留給 #387。

**還沒做的**：

- 30 分鐘固定門檻改成依傷勢嚴重程度計算的動態時長（面板顯示倒數）
- 純觀察模式下天神主動介入：點按昏迷中角色直接觸發送醫，不必等倒數結束
- 餓死／渴死／老化／瞬間死亡 Flag 這幾種死亡觸發源（目前完全沒有機制存在，
  跟 `health ≤ 0` 這條路徑無關，各自是獨立 issue，準備好 death_cause 文案後
  呼叫 `_die()` 收尾即可）
- 墓園／安葬（#380）、`corpse_decay` 達 100 自動立無名碑（#387）
