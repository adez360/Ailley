# 村莊地圖

`main.tscn` 的 `Node2D/TileMapDual` 是真實村莊地圖（issue #154），
取代了原本拿來驗尋徑的方塊測試圖。地圖範圍 tile x:-11..18、y:-11..10（30×22）。

不是一整塊開闊地：外框有樹籬邊界，多數地點各自圈在一塊有樹籬圍籬、留一個
缺口當入口的院子裡，院子之間是沒種樹籬的空地，走起來就是連接各院子的路。
另外散置 4 叢 2×2 的裝飾樹籬（不圍院子，純打斷大草皮的視覺變化）。
`cemetery` 是例外——只有一顆裸錨點，沒有圍院子（issue #380 落地時只放了
錨點，場景美術留待之後）。院子座標（外框矩形，樹籬圍住內部可走的空地，
缺口方向見下表）：

| 地點 | 院子外框（tile） | 缺口（入口） |
| --- | --- | --- |
| `home` | x:-10..-6, y:-6..-2 | 南側 `(-8,-2)` |
| `herb_shop` | x:-10..-4, y:3..7 | 北側 `(-7,3)` |
| `tavern` | x:8..13, y:1..5 | 西側 `(8,3)` |
| `pavilion` | x:2..6, y:-9..-5 | 南側 `(4,-5)` |
| `god_stone` | x:-1..3, y:1..5 | 北側 `(1,1)` |
| `herb_field` | x:13..17, y:-9..-5 | 西側 `(13,-7)` |

碰撞已用 `NavGrid`／`game_eval` 驗過：`solid=216`
（外框 100 ＋ 6 個院子圍籬扣掉缺口共 96 ＋ 4 叢裝飾樹籬 16 ＋ 場上既有 4 個
`StaticBody2D`），且從玩家出生點到每個錨點都找得到路徑，路徑終點與錨點座標
完全一致（`nav.find_path()` 的 `last` == 錨點 `global_position`）。

## PlaceAnchors 錨點

`Node2D/PlaceAnchors` 底下對應《規格書 07》的地點，錨點名稱就是
`Stats.SPEC`（`scripts/character/stats.gd`）與 `data/npc_schedule.json` 的
`place` 欄位直接引用的字串——**只有變更錨點名稱（識別字串）時**才需要這兩個檔案一起同步，
單純搬移 Marker2D 座標不會改變節點名稱、`resolve()` 也照常找到地點。
若未同步變更後的地點識別字串，`places.gd` 的 `resolve()` 會 `push_error` 且
靜默回傳 `Vector2.ZERO`。

| 錨點 | 位置 | 對應 `location_id` |
| --- | --- | --- |
| `home` | `(-120, -60)` | `loc_home` |
| `herb_shop` | `(-110, 90)` | `loc_herb_shop` |
| `tavern` | `(170, 50)` | `loc_tavern` |
| `pavilion` | `(70, -110)` | `loc_pavilion` |
| `god_stone` | `(20, 55)` | `obj_divine_stone` |
| `cemetery` | `(176, -112)` | `loc_cemetery` |
| `herb_field` | `(240, -112)` | `loc_herb_field` |

> [!note] 同一錨點多角色站位避讓（issue #657）
> `places.gd::resolve(place_name, character_id)` 帶了 `character_id` 時，
> 會在錨點座標外加一個依角色 id 雜湊算出的固定方向偏移（半徑 8px），不是
> 回傳錨點原始座標本身。多個角色被排到同一個地點（例如同時要去 `tavern`
> 吃飯）時因此會自然散開站，不會完全疊在同一個像素上，也不需要引擎追蹤
> 「這個地點現在站了幾個人」這種主動式排位狀態。同一個角色每次呼叫都拿到
> 同一個偏移（純函式、無狀態），移動中的抵達判定才不會追著一個一直在動的
> 目標跑。`character_id` 留空（debug 主控台、一次性座標查詢）維持舊行為，
> 直接回傳錨點座標。

工作站／販賣機見 [[工作站]]／[[販賣機]]。涼亭（`Pavilion`）與天神之石
（`DivineStone`）目前是純視覺佔位（`Polygon2D`，無碰撞、無腳本），各自是
對應 `Marker2D` 的子節點、本地座標 `(0,0)`——座標只有錨點這一份，不會有
移動錨點時視覺物件沒跟著搬的問題。兩者在 MVP 的 `available_actions` 都是
泛用行動（`rest`／`talk`／`move`／`idle`），天神之石的話語輸入機制本身
另有 issue，不需要互動腳本就能滿足這則的範圍。

## TileMapDual 填色陷阱：atlas 座標不是任選的

`addons/TileMapDual` 是 dual-grid 自動拼接外掛。`TileMapDual`（world/隱藏層）
與其子節點 `Display`（實際可見層）是兩層——直接對 world 層呼叫低階的
`tilemap_set_cell`／`tilemap_set_cells_rect`（`tilemap_manage` MCP 工具）可以填，
但**填的 atlas 座標必須帶有效的 `terrain` 自訂資料**，否則 Display 完全不知道
怎麼畫，畫面會變成一片空白／viewport 底色。

查一顆 tile 的 `terrain` 值：

```gdscript
var td = tile_set.get_source(0).get_tile_data(Vector2i(col, row), 0)
td.terrain  # -1 = 無效（純視覺變體，不能拿來畫）／0／1 = 有效 marker
```

本專案這顆 16 格 atlas 只有兩顆是有效 marker，其餘 14 顆是自動拼接用的
視覺變體（邊界/轉角混色，terrain 皆為 -1，只會出現在 Display 層，不要拿來填 world 層）：

| atlas (col,row) | `terrain` | 意義 | 有無碰撞 |
| --- | --- | --- | --- |
| `(2,1)` | `1` | 有地形（草叢／樹籬，會擋路） | 有 |
| `(0,3)` | `0` | 空地（可走） | 無 |

**要開闊、全部可走的地面就填 `(0,3)`**；要擋路的樹籬/障礙才填 `(2,1)`。
踩過的坑：一開始誤填 `(0,0)`（`terrain=-1`）畫面全黑，改填 `(2,1)` 又把整塊
地填成滿版障礙物（`NavGrid solid` 從 4 衝到等於總格數）——兩次都跑起來才發現。

## 改地圖／加錨點要開對場景檔：`main.tscn` 的 `Level` 是 `level.tscn` 的實例

`main.tscn` 裡的 `Node/Level` 是 `[node ... instance=ExtResource(...)]`，
本體定義在 `res://scenes/level.tscn`——`TileMapDual`／`NavGrid`／`PlaceAnchors`
全部是這個實例底下的節點。用 godot-ai MCP 直接對 `main.tscn` 開著的那份場景
操作 `/Node/Level/PlaceAnchors/...` 路徑（`node_create`／`tilemap_set_cell` 等）
看起來會成功、`scene_get_hierarchy` 也讀得到，但 `scene_save()` 存 `main.tscn`
時**不會把這些改動寫進磁碟**——它們是實例子節點的臨時記憶體狀態，
不是這個實例的 override，Godot 存外層場景時直接放棄未被登記為 override 的
實例內部改動。存檔呼叫回報成功、檔案大小/雜湊卻完全沒變，是這個問題的
症狀，容易誤判成別的環節出錯。

**正確做法：`scene_open("res://scenes/level.tscn")` 直接開本體場景來改**，
改完 `scene_save()` 存的是 `level.tscn` 自己，任何實例它的場景（目前只有
`main.tscn`）都會自動吃到新節點/新 tile，不用額外同步。
