# 滑鼠選取與鏡頭

用滑鼠指人、點人、把鏡頭交給他。四件事：

| 動作 | 反應 |
| --- | --- |
| 游標移到角色身上 | 描一圈白邊 |
| 點下去 | 點擊處冒一圈漣漪 |
| 點到角色 | 鏡頭改跟著他 |
| 點到空地 | 取消選取，鏡頭平滑移回玩家 |

主角是 `world/selection.gd`，掛在 `main.tscn` 的 `Node2D/Selection`（group `selection`）。
它只碰三樣東西：角色的 `get_pick_rect()` / `set_highlighted()`、鏡頭的 `follow()`，
以及自己畫的漣漪。

## 點得到的範圍 = 看得到的範圍

不走 Godot 內建的 physics object picking，改成自己拿目前影格的矩形去比。兩個理由：

- 角色的碰撞形狀只有腳下那一個小圓（半徑 6，還往下偏 6px）。
  照它算的話**點頭部會落空**，而人本來就是往頭上點。
- `Vision` 是半徑 5 格的 `Area2D`，而 `Area2D` 的 `input_pickable` 預設是 true。
  真的開 picking，游標會先被那一大圈視野吃掉，永遠點不到底下的人。

所以 `Character.get_pick_rect()` 回傳目前影格的 24×24 矩形（世界座標），
`Selection.character_at(point)` 掃 `characters` group 找誰的矩形罩住這個點。
兩個人站在一起時矩形會重疊，取**中心離游標最近**的那個。

## 點擊座標取自事件，不是當下的游標位置

`_unhandled_input` 裡不用 `get_global_mouse_position()`，
改成把事件自己的 `position` 換算成世界座標：

```gdscript
get_canvas_transform().affine_inverse() * mouse.position
```

真人操作時兩者一樣，但事件是被餵進來的（自動測試、日後的重播）時，
前者讀的是「游標現在在哪」，跟那一下點在哪沒有關係。
hover 偵測則相反，它問的就是「游標現在在哪」，所以照樣用 `get_global_mouse_position()`。

## 描邊 shader 一定要知道影格範圍

`assets/shaders/character_outline.gdshader`。做法是取樣上下左右四個鄰居，
自己透明而鄰居不透明的像素就塗成白色。

> [!warning] 不夾住影格範圍會描到隔壁影格
> 角色的圖是 sprite sheet 切出來的 `AtlasTexture`，UV 走的是**整張圖集**的座標，
> 而相鄰影格之間沒有留白。取樣鄰近像素時不設限的話，
> 描出來的是隔壁那一格的身體輪廓，貼在自己身上。

所以 shader 有一個 `region` uniform 裝「本影格在圖集裡的 UV 範圍」，
超出範圍的取樣一律當成透明。`Character._sync_outline_frame()` 負責餵值，
並訂了 `frame_changed` 與 `animation_changed` 兩個訊號 ——
**兩個都要訂**：換動畫時影格編號可能沒變（都是 0），只有 `animation_changed` 會發。

材質是第一次被指到才建，沒被指到過的角色不會多背一份。

## 鏡頭不再掛在 Player 底下

`world/follow_camera.gd` 現在是 `main.tscn` 的 `Node2D/Camera2D`（group `follow_camera`），
每個物理幀把自己對齊 `_target.global_position`。

掛父子關係換對象要 reparent，而且**鏡頭會跟著對方一起被移除** ——
角色離場時鏡頭就沒了。現在改成持有對象的參照，對象失效就退回玩家。

換對象時的平滑是 `Camera2D` 自己的 `position_smoothing`（速度 8），
腳本不另外插值。跟隨用 `_physics_process` 是因為角色也在物理幀移動，
用 `_process` 會永遠慢一幀。

邊界的算法沒變：`_ready` 依 TileMap 的實際範圍算，不寫死座標。
