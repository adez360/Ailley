# 滑鼠選取與鏡頭

用滑鼠指人、點人、把鏡頭交給他。四件事：

| 動作 | 反應 |
| --- | --- |
| 游標移到角色身上 | 描一圈白邊 |
| 點下去 | 點擊處冒一圈漣漪 |
| 點到角色 | 鏡頭改跟著他 |
| 點到空地 | 取消選取，鏡頭平滑移回玩家 |

主角是 `world/selection.gd`，掛在 `main.tscn` 的 `Node2D/Selection`（group `selection`）。
它只碰三樣東西：角色的 `get_pick_rect()` / `set_highlighted()`、鏡頭的 `follow()`，
以及自己畫的漣漪。

## 點得到的範圍 = 看得到的範圍

不走 Godot 內建的 physics object picking，改成自己拿目前影格的矩形去比。兩個理由：

- 角色的碰撞形狀只有腳下那一個小圓（半徑 6，還往下偏 6px）。
  照它算的話**點頭部會落空**，而人本來就是往頭上點。
- `Vision` 是半徑 5 格的 `Area2D`，而 `Area2D` 的 `input_pickable` 預設是 true。
  真的開 picking，游標會先被那一大圈視野吃掉，永遠點不到底下的人。

所以 `Character.get_pick_rect()` 回傳目前影格的 24×24 矩形（世界座標），
`Selection.character_at(point)` 掃 `characters` group 找誰的矩形罩住這個點。
兩個人站在一起時矩形會重疊，取**中心離游標最近**的那個。

## 點擊座標取自事件，不是當下的游標位置

`_unhandled_input` 裡不用 `get_global_mouse_position()`，
改成把事件自己的 `position` 換算成世界座標：

```gdscript
get_canvas_transform().affine_inverse() * mouse.position
```

真人操作時兩者一樣，但事件是被餵進來的（自動測試、日後的重播）時，
前者讀的是「游標現在在哪」，跟那一下點在哪沒有關係。
hover 偵測則相反，它問的就是「游標現在在哪」，所以照樣用 `get_global_mouse_position()`。

## 描邊 shader 一定要知道影格範圍

`assets/shaders/character_outline.gdshader`。做法是取樣上下左右四個鄰居，
自己透明而鄰居不透明的像素就塗成白色。

> [!warning] 不夾住影格範圍會描到隔壁影格
> 角色的圖是 sprite sheet 切出來的 `AtlasTexture`，UV 走的是**整張圖集**的座標，
> 而相鄰影格之間沒有留白。取樣鄰近像素時不設限的話，
> 描出來的是隔壁那一格的身體輪廓，貼在自己身上。

所以 shader 有一個 `region` uniform 裝「本影格在圖集裡的 UV 範圍」，
超出範圍的取樣一律當成透明。`Character._sync_outline_frame()` 負責餵值，
並訂了 `frame_changed` 與 `animation_changed` 兩個訊號 ——
**兩個都要訂**：換動畫時影格編號可能沒變（都是 0），只有 `animation_changed` 會發。

材質是第一次被指到才建，沒被指到過的角色不會多背一份。

> [!warning] shader 裡的 `base` 要讀 `COLOR`，不要自己重新取樣 `TEXTURE`
> `fragment()` 一開始的 `base` 若寫成 `texture(TEXTURE, UV)`，取到的是完全沒
> 套用 `sprite.modulate`／`self_modulate` 的原始像素——`COLOR` 這個內建變數
> 在 `fragment()` 開頭才是已經乘上 modulate 的顏色。死亡角色靠
> `_apply_death_tint()` 把 `modulate` 調成灰色（見 [[Character 基底與 Agent]]），
> 描邊材質生效的當下若 `base` 繞過了 modulate，屍體會在滑鼠指到時瞬間變回
> 原色，鬆開滑鼠才變灰（issue #828）。`alpha_at()` 抓鄰近像素透明度用的是
> 原始 `TEXTURE` 取樣，這個不用改——只有 `base` 這個「本像素最終顏色」需要
> 尊重 modulate。

## 鏡頭不再掛在 Player 底下

`world/follow_camera.gd` 現在是 `main.tscn` 的 `Node2D/Camera2D`（group `follow_camera`），
每個物理幀把自己對齊 `_target.global_position`。

掛父子關係換對象要 reparent，而且**鏡頭會跟著對方一起被移除** ——
角色離場時鏡頭就沒了。現在改成持有對象的參照，對象失效就退回玩家。

換對象時的平滑是 `Camera2D` 自己的 `position_smoothing`（速度 8），
腳本不另外插值。跟隨用 `_physics_process` 是因為角色也在物理幀移動，
用 `_process` 會永遠慢一幀。

邊界的算法沒變：`_ready` 依 TileMap 的實際範圍算，不寫死座標。

## 別的節點要重用同一顆點擊，會踩到的兩個坑

`ui/status_panel.gd`（點角色彈出狀態表）跟這裡搶同一顆滑鼠左鍵，踩出來的教訓：

> [!warning] 兩個 `_unhandled_input` 搶同一個事件，誰先誰後別用場景樹位置猜
> `Selection._unhandled_input` 不管有沒有點中角色都會 `set_input_as_handled()`。
> 另一個也用 `_unhandled_input` 監聽同一顆左鍵的節點，實測**先後順序跟場景樹位置
> 對不上**（後加的節點反而後收到，猜的「後加的先收到」是錯的）。
> 想保證某個節點一定比 `_unhandled_input` 系的搶先看到輸入，改走 `_input`——
> 這是輸入管線裡順序固定、不受場景樹位置影響的一關，跟 `debug_console.gd`
> 用它擋掉遊戲世界輸入是同一個理由。

> [!warning] 彈出的面板剛好蓋住點擊處，GUI 層會把事件吃掉
> `StatusPanel.Panel` 用 `_input` 判定成功、`panel.show()` 之後，
> 同一個事件接著會進 Godot 的 GUI 階段（`_input` → GUI → `_unhandled_input`）。
> 這個面板置中，玩家又常常也在螢幕中心附近 —— 面板一顯示就剛好蓋住剛剛點的座標，
> `Panel` 預設 `mouse_filter = STOP` 會把同一下點擊吃掉，事件到不了
> `Selection._unhandled_input`，鏡頭跟隨悄悄失效（面板本身沒事，因為它在 GUI
> 階段之前就已經處理完了）。純顯示、不需要接收滑鼠的 Control 都要設
> `mouse_filter = MOUSE_FILTER_IGNORE`，別讓它們默默擋路。

`Character` 目前沒有點擊本身以外的互斥狀態，所以「點角色→開狀態表」跟
「點角色→鏡頭跟過去」這兩件事故意設計成**同時發生**，不互相取消 ——
`status_panel.gd` 判定完之後不呼叫 `set_input_as_handled()`，讓事件繼續往下傳。
